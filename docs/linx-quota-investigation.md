# 灵矽原生并发、额度与止付能力调查

2026-10-24；代码基线 `b6e33f32c8fd3f2dce2875c415f3df97259359f5`。仅查官方公开文档和现有文档连接器schema，没有读取管理key、调用账号API、登录控制台、创建或修改资源、建立语音连接或消耗推理。

**结论：能确认供应商会核算可用额度，并可能因不足而结束在途设备会话；目前没有足够公开依据把它当成“可自行配置、保证即时生效的并发/消费硬上限”。不能据此承诺公开体验的总费用封顶，也不能断言供应商没有这些能力。**

## 已确认的边界

UID小时包按设备会话持续时间乘以模型、音色的附加倍率折算，不是只按玩家实际说话计时；新配置的倍率从新会话开始采用。正式用量按日聚合，展示余额会延迟，其他可用额度也可能先被使用。官方对实时额度不足的表述是“平台可能会结束当前设备会话”，没有给出强制切断时点或最大超额承诺。[资源包时长扣减规则](https://linx.qiniu.com/docs/xrobot/billing/resource-usage-billing)

这里的“可能”不能改写成“一耗尽必定立即停服”；“其他可用额度”也不能自行解释成“必定自动扣现金余额”，扣减来源和顺序仍需确认。索引仍有旧 `/guide/resource-usage-billing` 地址，本次直开该路径404；上面从计费目录点击得到的 `/billing/` 正文可访问。[计费目录](https://linx.qiniu.com/docs/xrobot/billing/)

## 已有参数为什么不能代替费用闸门

智能体支持 `extra.goodbye.idle_timeout_seconds`（60–3600秒）；这是空闲断连，不是持续互动会话的绝对寿命或账号预算。`extra.llm.max_tokens`限制单次回答长度，不是累计消费上限。没有从这些参数推导出账号级硬止付。[智能体API](https://linx.qiniu.com/docs/xrobot/api/agent)

推断：浏览器的每局8分钟是玩法规则，不能作为不可绕过的服务费控制。供应商按连接起止计时的口径与浏览器排除准备期的玩法口径也不同；刷新或并发用户的总量不能只用单局额度估算。无传统backend/DB的方向仍可保持，但是否能仅依赖供应商原生限额作为成本边界，本次资料不足以确认。这里没有引入任何新部署或实现决策。

## 需供应商明确回答的最小问题

1. 能否为本项目独立agent、应用或子账号设不可超出的并发数和消费额度？请给出配置入口/API、作用粒度及上限是否原子执行。
2. UID资源包/现金余额耗尽后是否转扣其他来源、允许欠费或自动按量续扣？能否明确关闭所有自动续扣并设置总支出上限？
3. 到达上限或修改上限时，已连接WSS与已签发设备token如何处理，最长生效延迟、最大额外扣费窗口是多少？是否有区别于告警的硬阻断承诺？

这些问题尚未发送给供应商，没有联系任何第三方或要求用户现在操作。若账号控制台有额外未公开选项，可以在用户授权的后续核实中读取，但不能将其提前记为已支持。
