# 持续语音能力实验记录

2026-10-23；独立实验，**不是生产实现验收**。用户已批准先做受控验证，通过后按已确认方案实施；本次仅新增可重跑探针和证据，不修改应用、现用8787服务、麦克风、用户设备或供应商现有角色。

## 输入、隔离与预算

本机macOS内置say（中文Eddy）合成两句无敏感问句，FFmpeg转换PCM16 kHz、单声道、16-bit little-endian。长度分别75,536和84,750字节，末尾不足640字节的帧补零。该音频按每20 ms一帧640字节上传，句间及回答期间持续发送静音。没有回灌供应商TTS输出，因此不包含回声场景。

使用新建的1个 `LIE-realtime-test-*` 通用agent、3个专用绑定设备，只使用第一设备做此次连接。Memory_nomem、chatHistoryConf=0，经readback确认。两段语料仅各合成一次，真实供应商回答4次、无重试，未触及额度错误。独立0600状态与音频均在探针ignored tmp内。

## 实际结果

**协议基线通过**：一条WebSocket、一条realtime listen.start；没有listen.stop、listen.detect或客户端abort。两次句后停顿都自动产生回答，普通stop后第二轮能继续；第三轮回答时插入合成问句，服务端发aborted stop，然后第四轮恢复。

| 事件 | 从开始连接计时 |
| --- | ---: |
| WS open | 1,795 ms |
| hello | 2,234 ms |
| realtime start、第一句开始上传 | 2,236 ms |
| 第一句上传结束 / STT | 4,737 / 5,599 ms |
| 第一轮context / TTS start / 普通stop | 6,632 / 8,205 / 14,855 ms |
| 第二句开始 / 结束 / STT | 14,866 / 17,651 / 18,783 ms |
| 第二轮context / TTS start / 普通stop | 19,931 / 21,922 / 28,766 ms |
| 第三句开始 / STT / context / TTS start | 28,781 / 32,190 / 33,267 / 35,646 ms |
| 插话开始 / aborted stop / 插话结束 | 35,897 / 38,513 / 38,654 ms |
| 第四轮 STT / context / TTS start / 普通stop | 39,668 / 42,168 / 43,807 / 51,319 ms |

合计：4 STT、4次角色context工具调用、4次TTS start、4次stop（其中1次is_aborted=true），1,185帧返回PCM、758,400字节。aborted stop至下一次TTS start之间观察到**0帧迟到音频**；这只是本次顺序，不是协议全局保证。无逐轮音频ID，不能因此删除生产迟到事件防护。

第一句上传结束到STT约862 ms、到TTS start约3,468 ms；第二句对应1,132 / 4,271 ms。插话开始到aborted stop约2,616 ms：证明自动打断可发生，**还没有达到“开口就立即停声”的体验证明**。没有浏览器播放器，本次不能将TTS start称为用户听到首音，也不能确认真人说话起点/停顿阈值。四次STT的计数和工具调用通过，未对识别文本做逐字准确率评价。

listen.start携带温暖阿虎/Alvin的voice.id `29ddb9582ae8481ebf11562f99aeaf95`，连接未拒绝且随后正常输出；未提供音色选中ack、未试听对照，故仅报告带参数的会话可运行，不能宣称实际听感切换已确认。MCP返回同一虚构人物context；未用本次单角色实验替代之前的角色隔离测试。

## 后续验收缺口

- 在独立设备、用户授权的真实浏览器麦克风下验证连续三轮、两次打断及恢复；重点检查插话停止播放延迟和开头音节是否丢失。
- 耳机基线与外放AEC/噪声；当前无扬声器反馈，不知道是否会自打断。
- 浏览器收到is_aborted后实际清队列、已显示转写保留、新TTS恢复；真实音频听感和音色对照。
- 同人物长连接中MCP每轮调用的稳定性，未听完内容是否被视为已告知；切人/重开/断线及并发设备隔离；显式停止/后台隐藏后无采集。不能将4/4工具调用当作模型永久保证。
- 保留网关3分钟上限，测试边界；公开访问/设备分配不在此实验中解决。

下一步先准备独立浏览器能力测试入口，验收真人收音、播放、回声与打断；主应用改造仍以能力验收为门槛。若用户要求低于当前约2.6秒的插话停声延迟，应先讨论端侧检测/供应商调参，不能擅自引入端侧VAD改变方案。

## 清理与可复现性

探针见 `spikes/realtime-voice/README.md`、`resources.ts` 和 `probe.mjs`。真实执行一轮后立即运行cleanup；首次清理在第一请求TLS握手前遭遇ECONNRESET；检查状态仍保留1agent/3绑定设备后，仅重试管理清理，三次解绑及agent删除全部HTTP200/code0，cleanup complete，私密状态文件已删除。资源步骤失败会保留状态，不能先删状态假装清理完成。代码语法检查及diff检查之外，本实验的有效检查就是以上真实协议运行，不用fake-provider冒充供应商验证。
