## 判断

**需要补几处关键说明，目前没有充分依据增加一套首次教程。** 首页与接案页已经能说明语音推理、选择案件、询问和指认；江苏双人短案还提供了具体开口方向。缺口主要是玩家无法从界面事先可靠得知的规则：共享计时如何工作、点人物立即提交以及错指的终局后果。另有语音失败反馈过于笼统的问题，不能靠教程替代实际错误反馈。

这是基于当前源码的专家走查，尚不能证明真实新用户会在哪一步卡住、卡住比例或帮助能提升多少完成率。没有浏览真实案件、调用 provider、麦克风或 WebSocket，也没有读取用户草稿、Cookie 或浏览器 storage；未启动服务。

## 方案比较

| 方案 | 收益与代价 | 本轮建议 |
| --- | --- | --- |
| 不新增帮助 | 进入最快；依赖现有提示和短案，但规则缺口继续存在。 | 不优先：计时和终局后果已可从源码确定缺失，无须等真人受挫才说明。 |
| 就地补文案 | 在开启对话、计时、指认发生处讲必要信息；无存储和首次判定，对分享直达与回访者同样有效。 | **推荐最小方案。** 先讨论三处文案，再决定是否需要折叠较长解释。 |
| 随时可打开的轻帮助 | 容纳规则回查与保守设备检查；会多一个入口，也可能少人主动打开。 | 有真人观察需求后再加。不能把关键后果只藏在这里；打开帮助是否继续计时必须明确，不能暗改暂停规则。 |
| 可跳过的一次性提示 | 能主动触达，但增加打断、关闭和重现成本；无法保证真正第一次使用或被阅读。 | 目前证据不足。不要先建设首次状态、全屏轮播或强制教程。 |

## 推荐的最小补充（待用户讨论）

不增加必经页面、首访状态或案件字段；不改计时、指认、错误恢复规则。正式版式尚未设计。

1. **开启对话附近 / 无记录时的提示**：拟文案“点击「开启对话」，允许使用麦克风后直接说话，不用按住按钮。可以围绕案件自由提问。”已有等待提示继续负责“现在能否开口”。不展示案件答案或把示范问法变成必选问题；江苏案已有具体开场，不重复教攻略。
2. **剩余额度附近的简要规则**：拟文案“所有人物共享询问时间，结束对话后暂停。”需要更多说明时，用就地展开补充：“连接准备不计时；连接就绪后，说话、停顿、等待和回答都会计时。切换人物沿用剩余时间；用完后仍可回看并指认。”若说明在活跃对话中展开，仍沿现行规则计时，应明示“查看说明不会暂停；需要思考时可先结束对话”。不把供应商连接上限混作游戏额度。
3. **指认弹窗里、人物选项前**：拟文案“点击人物会立即提交，结束本局；选错不会揭晓答案。”保留当前返回调查入口。此项是补后果说明；不能声称能防止误触，也不代替待讨论的“选人后确认”方案。

三处中，计时和指认后果是高置信需求；开口提示是低成本候选，具体长度和展示时机仍需判断是否与当前空态重复。若先缩范围，可只补前两项规则缺口（计时、后果），再通过观察决定开口提示。不要在首页先塞完整规则。

## 可选真人观察（未执行）

用户决定是否邀请 3–5 位没玩过的人，允许本人操作并事先同意语音/可能的服务费用。本研究不自动发起真实测试、招募或录音。

- 给首页和任务“选一个案件试着玩到你愿意作出判断”，不给教程、不提示点哪个按钮；观察是否理解目标、选案和开口。第一次不先询问规则，避免问题本身成为引导。
- 在自然暂停时询问“你觉得现在还在用询问时间吗，换个人会怎样？”记录原话及是否主动找说明，不以会背规则作唯一指标。
- 第一次准备指认时、实际点击人物之前，询问“你预计点下去会发生什么？”随后由参与者自行决定，不让测试迫使其错选或泄露答案。
- 观察能否回看、切人和退出。权限失败若自然出现，观察能否恢复；不要人为拒绝权限后再声称是自然发生率。
- 区分未发现按钮、误解文案、规则不可见、语音技术故障和推理难度；记录是否需要协助及协助内容。少量样本用于找具体障碍，不给转化率/统计显著性结论。
