更新：2026-10-23。范围：桌面浏览器 Web、单人自由语音推理、3 名嫌疑人、2–3 天 MVP。已完成下述只读管理 API 预检；语音、模型扮演、MCP 和会话隔离仍未实测。

| 请求 | HTTP / 业务码 | 结果 |
| --- | --- | --- |
| `GET /xiaozhi/agent/list?limit=20` | 200 / 0 | 当前账号返回 0 个智能体，无后续分页 |

## 结论与推荐

现有文档依据下，可验证的候选是 **浏览器 → LIE WebSocket 网关 → 灵矽语音 WebSocket**；网关能否使用 serverless 而不运行传统常驻服务端，需要另行核验运行平台。灵矽负责 ASR、模型和 TTS，LIE 维护案件、证据、角色知识和结案规则。先验证一个角色，再验证证据同步、三角色隔离与跨局清理，完成后再确定连接复用策略。以下服务端权威状态、云端 MCP 是架构提案，不应被解释为用户已经确认必须运行传统服务端。

有两个必须先解决的接入条件：浏览器无法通过原生 WebSocket API 设置灵矽要求的握手头；文档虽然支持 PCM 输入，但不能据此认定输出也是 PCM。另一个关键未知是灵矽的历史恢复和长期记忆范围，不能把新 WebSocket 或新 session_id 等同于新游戏。

## 官方文档已确认的事实

### 连接、音频与事件

- 语音通道要求 `Authorization`、`Device-Id`、`Client-Id`、`Protocol-Version` 握手头；连接后交换 `hello`，再发送音频二进制帧与 JSON 控制消息。`hello.agent_params.custom_replace_prompt` 可替换提示词占位符，但文档仅说明建连时使用。
- 输入示例有单声道 16 kHz Opus，以及 PCM signed int16 little-endian、20 ms 帧；PCM 示例的 `frame_size: 320` 应核验单位，320 个采样点在此格式下为 640 字节。
- TTS 专章明确输出为 Opus，16/24 kHz，20/40/60 ms 帧。因此必须按返回参数配置解码，不预设双向 PCM，也不把原始 Opus 包当作 WebM 文件播放。
- `listen.mode = realtime` 用于全双工和人声打断；有 `abort`、`stt.text`、`tts.sentence_start.text` 及 `tts.stop.is_aborted`。打断时需清空本地播放缓冲。

来源：[WebSocket 协议：请求头、Hello、控制消息、服务器输出音频参数](https://linx.qiniu.com/docs/xrobot/platform/websocket)。

### 桌面浏览器的接入限制

浏览器原生构造器仅接收 URL 和可选 subprotocol，没有任意请求头参数。因此照搬硬件 SDK 的握手方式无法直接用于浏览器。[WebSocket 构造器](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/WebSocket)

本次检查的灵矽目录、WebSocket、第三方应用接入、客户端 demo 页面中，**未找到语音 WebSocket 的浏览器 SDK，或通过 query / subprotocol 代替上述鉴权头的公开方案**。这表示“本次未查到”，不表示产品一定不支持；可向供应商核实。

官网客户端 demo 是 C++ 的 Linux/macOS 音频客户端，包含 Opus 和 WebSocket 实现，可参考协议行为，不能直接作为浏览器 SDK。[客户端 demo](https://linx.qiniu.com/docs/xrobot/guide/client-demo)

MCP Proxy 文档确有 query token 的 WebSocket 地址，但用于 MCP 工具代理，不能据此推断语音通道也支持同样鉴权。[MCP 服务接入指南：MCP Proxy](https://linx.qiniu.com/docs/xrobot/guide/mcp-store)

### 无传统服务端 / 纯前端可行性（补充调查）

**截至本次公开资料调查，纯静态前端直接接入灵矽语音仍未确认；不能证明不存在。无需传统常驻服务端则仍是可评估方向，不能与纯静态划等号。** 区分如下：纯静态只有浏览器代码与静态资源；serverless / 云 Worker 仍执行我们部署的远程代码，可以承接鉴权或中转；浏览器 Web Worker 只是用户设备上的执行线程，不是远程中转，不能消除 WebSocket 握手限制。

| 证据 | 强度与可得结论 | 仍不能据此认定的事项 |
| --- | --- | --- |
| 官方协议明确语音 WS 的 Header 鉴权，浏览器 API 无自定义 Header 参数 | 强：照文档字面接入需要能补 Header 的环节 | 未证明服务实际只接受这种鉴权，也未证明必须用传统服务器 |
| 官方快速入门提到 web-demo / 网页体验；智能体配置指引明确有“网页体验：拨打智能体” | 强：平台确实提供网页体验能力；中等线索：存在浏览器相关实现 | 控制台可能使用自身代理、内部接口或专用凭证；不能推出第三方站点可用的公开 SDK、纯静态直连或可复用协议 |
| OTA 示例名是 xiaoling-web-test | 弱：存在 Web 测试命名线索 | 不等于原生浏览器已能设置其要求的 Header，也不证明 CORS、设备发放和可公开令牌策略已解决 |
| 检查文档目录、语音 WS、第三方接入、demo、OTA、快速入门、配置指引，并检索浏览器 SDK / query 鉴权 / 临时令牌 / WebRTC / HTTP 流式语音 | 有限的否定性证据：本次未找到面向第三方站点的正式浏览器语音 SDK、替代语音鉴权或独立 HTTP ASR/TTS 推理接口说明 | 搜索未命中不能证明能力不存在；MCP Proxy query token 和第三方业务 SSE 都不是语音直连接口 |

网页体验来源：[快速入门：保存配置与记忆说明](https://linx.qiniu.com/docs/xrobot/guide/quick-start)、[智能体配置操作指引：先认识页面](https://linx.qiniu.com/docs/xrobot/guide/agent-config)。公开控制台 [智控台](https://xrobo.qiniu.com/) 在本次网页抓取中仅返回需 JavaScript 的应用壳，未登录，也未验证其实际通信链路。公开可见的官方链接示例仍为前述 C++ 客户端；未把第三方搜索结果当作官方方案。

**凭证需要分开判断。** 平台用户登录 Token / API Key 用于设备和智能体管理，不能因为设备语音 token 存在就把管理凭证放入客户端。OTA 返回的 token 是设备语音凭证；现有文档没有给出适合公开网页分发的有效期、单局作用域、可撤销性、额度隔离或 Origin 约束保证。因此“设备 token 一定不可暴露”和“它是安全可公开的临时 token”都还没有文档依据；可否交给浏览器使用，需要供应商明确策略与实际鉴权方案共同确认。即使供应商提供短期 token，仍须解释它如何通过浏览器可用的握手机制提交。

**MCP 不必一概采用云端。** 云端 MCP 方案明确需要平台可访问的外部 `/mcp` SSE 与 `/mcp/message` 接收端点，所以若选它，单纯静态托管不够；serverless 能否承接长连接与回调由运行平台决定。[云端 MCP：环境要求](https://linx.qiniu.com/docs/xrobot/mcp/software-mcp)

端侧 MCP 则把 JSON-RPC 包在现有 WS 的 `type: mcp` 消息中，平台发起 initialize、tools/list、tools/call，由设备端返回结果，不要求另建公开 HTTP MCP 端点。由此推论：只要语音通道和工具调用能力可用，浏览器主线程或浏览器 Web Worker 可以实现这组消息处理，云 Worker 也可以中转或实现；这是协议可移植性的推论，尚无本项目实测或官方浏览器示例背书。它能去掉独立云端 MCP 服务，却不能解决语音 WS 鉴权，也不能自动提供客户端状态的可信性与剧透保护。[端侧 MCP：典型使用流程、协议格式规范](https://linx.qiniu.com/docs/xrobot/mcp/hardware-mcp)

下一步最有价值的供应商资料是：网页体验是否提供可复用 SDK/公开示例；第三方浏览器语音通道的鉴权方法；设备令牌是否允许下发及其限制；若声称有 HTTP 流式语音接口，则提供正式 endpoint、CORS、输入输出格式和鉴权说明。在得到这些资料前，纯静态是待验证候选，网关也只是可用的候选职责，可由适配的 serverless 运行时承接。

### 设备注册与鉴权

OTA 使用设备标识和 Client UUID 上报，返回激活信息或连接配置。设备绑定后才返回语音 WebSocket token，绑定完成后需再次 OTA 获取。文档允许 MAC 或由硬件 ID 生成的伪 MAC，示例包含 `xiaoling-web-test`，但没有明确承诺任意浏览器虚拟设备的生产接入、批量注册或并发政策。[OTA 协议：请求头、成功响应、快速激活状态检查](https://linx.qiniu.com/docs/xrobot/platform/OTA)

已有设备绑定 API 使用激活码绑定到指定智能体。平台管理凭证与 OTA 返回的设备语音 token 用途不同，实现时分别管理，均保留在服务端。[设备 API：绑定设备](https://linx.qiniu.com/docs/xrobot/api/device)

### 三角色与新一局

- 连接握手 `X-Agent-ID` 可指定智能体。会话中改 `agent_params.voice` 只改变音色，并保持上下文，不能作为角色隔离机制。[智能体与音色切换](https://linx.qiniu.com/docs/xrobot/platform/agent-voice-switch)
- `PUT /v1/devices/{mac_address}/agent/{agent_id}` 是设备绑定切换；默认会迁移设备全部聊天历史，显式 `disable_chat_history_migration: true` 才不迁移。历史不迁移仍不等于运行中会话已隔离。[智能体 API：切换设备关联智能体](https://linx.qiniu.com/docs/xrobot/api/agent)
- `DELETE /v1/devices/{mac_address}/chat-history` 可删除设备历史，支持 `agent_id` 范围。文档只承诺数据库记录删除；音频不会立即删除，且未承诺清理活跃上下文或长期记忆。因此重开必须单独验证。[聊天记录 API：删除设备聊天历史](https://linx.qiniu.com/docs/xrobot/api/chat-history)

### MCP 与证据状态

云端 MCP 使用 JSON-RPC 2.0，可自建服务。平台调用时在 HTTP 头携带 `X-Linx-Device-Id`、`X-Linx-Agent-Id`、`X-Linx-Session-Id`，这些标识不会自动填入工具 arguments；可据此由服务端映射游戏局与当前角色。[云端 MCP：环境要求、HTTP Header 参数](https://linx.qiniu.com/docs/xrobot/mcp/software-mcp)

**我们的设计提案：** UI 出示证据先由 LIE 服务端校验并写入该局该角色状态，增加 `stateVersion`；角色回答前调用 `get_interrogation_state`，仅返回该角色可知信息、已向他出示的证据和允许发生的态度变化。案件完整真相及其他角色秘密保留在服务端，不作为通用上下文直接发送给模型；该角色本来知晓的事实也应经过角色视角过滤。工具按服务端绑定定位游戏与角色，禁止相信模型自报 sessionId、characterId 或“玩家拥有证据”的说法。以上工具名、版本和过滤规则是 LIE 自己要实现的约定。

文档没有保证“每轮一定先调用工具”，也没有保证 UI 写状态后自动注入当前模型上下文。需验证提示词能否稳定要求读取新状态，以及工具调用到回答的时序。证据动作提交中时暂停发起下一轮；提交成功后再接受提问，记录本轮观察到的 stateVersion。若工具漏调，不能宣称状态同步可靠，应评估由网关重建连接并在 hello 提供当前角色快照；该替代方式的历史恢复也必须验证。

### LLM API 的边界

官方“大语言模型 API”描述模型配置的创建、编辑、查询、删除，以及将配置应用到智能体；文中的 OpenAI base_url 是被配置模型的地址，**不能据此假设灵矽向我们开放了通用文本推理 endpoint**。[大语言模型 API](https://linx.qiniu.com/docs/xrobot/api/llm)

“第三方业务系统接入”的 Chat 模式是灵矽把识别文本发给我们的业务服务、等待我们提供文字回复；它不是灵矽模型的推理 API。它可作为将来业务编排的入口，但当前缺少独立的灵矽推理接口，不宜作为首选方案。[第三方业务系统接入：Chat 对话模式](https://linx.qiniu.com/docs/xrobot/guide/third-app)

## 两个候选架构

| 候选 | 组成与收益 | 成本与前提 | 建议 |
| --- | --- | --- | --- |
| A：服务端网关 | 浏览器采集 PCM；网关补齐鉴权头、管理连接、转发事件；灵矽处理语音与模型；云端 MCP 读取游戏状态。网关可解码 Opus 后向浏览器发送 PCM，避免前端直接解原始 Opus | 多一跳；需服务端 Opus 解码组件、流控与打断队列处理。先核验 PCM 输入和 Opus 输出实际格式 | 推荐用于当前 MVP，协议已有文档依据 |
| B：供应商正式 Web SDK / 浏览器鉴权方案 | 浏览器与灵矽直接连语音，LIE 服务端仍维护状态与 MCP | 目前未找到正式公开方案；需要供应商提供文档与示例，并证明临时凭证范围、原始音频播放、角色隔离可行 | 仅在供应商给出可验证材料后考虑，不作为排期前提 |

首个游戏的候选部署策略是 3 个智能体配置、3 个互相独立的逻辑通道。优先核实能否为每个演示席位分配 3 个专用虚拟设备，逐一绑定角色以减少共享历史风险；这只是待确认的设备分配方案。通用引擎从内容包读取角色集合与规则，不硬编码角色数、剧情、提示词或 agentId，新增同类审讯游戏应只需新增内容包。

由 provider binding 层维护 `(gameId, gameVersion, sessionId, characterId) → (provider, deviceId, agentId, providerSessionId)`：gameId/gameVersion 标识该局固定使用的内容包，sessionId 是 LIE 游戏局标识，characterId 是包内角色标识；providerSessionId 专指灵矽连接返回的会话标识，避免与游戏局混淆。绑定由服务端解析，stateVersion 属于该局游戏状态。平台 agentId/deviceId/会话标识属于部署配置与运行数据，不进入剧本本体。不把同一段完整审讯历史传给全部角色。更完整的引擎与内容包约定见架构文档。

连接保持还是重建由实际并发限制、空闲超时、切换延迟与上下文恢复结果决定。即使只让当前角色保持连接，LIE 自己仍保存每人的对话和状态。对方是否知道别人的证词由案件规则控制，玩家复述证词属于新的说法，不自动升级为系统事实。

## 尚待供应商确认或真实环境验证

1. Web 虚拟设备接入与激活方式、每账号设备数、每设备并发连接、X-Agent-ID 的权限与设备绑定约束。
2. PCM 输入是否在选定模型/音色配置下可用；实际输出参数、Opus 包边界、有无协议头；是否有可协商的 PCM 输出。
3. 同一设备三智能体的历史检索/记忆范围；重连是否恢复旧对话；能否禁用长期记忆与摘要，关闭、删除历史后多久生效。
4. MCP 每轮查询的可靠性、超时行为、工具错误是否泄露内部数据；读到的新证据是否在该轮正确影响回答。
5. 实际首音延迟、打断延迟、回声误触发、连续对话稳定性、费用与断线恢复。任何数字应从测量得出。

## 验证清单与记录方式

所有项目当前均为“未执行”。先使用无剧透的测试角色和虚构标记词，避免内容设计干扰协议验证。每次记录浏览器/系统、配置版本、模型/音色类别、gameId、gameVersion、LIE sessionId、characterId、providerSessionId、事件时间、stateVersion、结果与脱敏日志；不记录凭证。

| 验证 | 操作 | 通过条件 |
| --- | --- | --- |
| 鉴权与握手 | 专用测试设备完成绑定与 OTA；网关连接，发送 hello；再测过期凭证 | 有有效 hello；能取得/关联会话标识；错误可解释且客户端可恢复；平台凭证未发给浏览器 |
| 一个角色问答 | 连续进行 10 轮语音问答，包含人名、时间、短追问；记录输入结束、STT、首个 TTS 和首音时间 | 问题被识别、文字与声音对应、无丢句或重播；记录实际延迟分布，再由产品确定体验阈值 |
| 双工与打断 | AI 回答中开口；另做主动 abort；重复 10 次 | 旧声音和排队音频被清除；新提问只发送一次；旧字幕有中断标识；扬声器回声不造成持续自我打断 |
| 证据动作 | 先问固定问题，再从 UI 向 A 出示测试证据；提交成功后问同一问题；另试口头虚构未持有证据 | 工具日志与本轮 stateVersion 一致；角色回应受新证据影响；口头虚构未改变正式证据状态；工具失败不伪装成功 |
| 三角色往返 | 仅向 A 说秘密标记甲，向 B 说乙，向 C 说丙；按 A→B→C→A→C→B 追问 | 各自能记住自己的标记/证词；不得知道未获知的他人标记；音色、字幕、证据与当前角色一致；重复 3 轮 |
| 跨局清理 | 第一局告知三人独有标记并改变证据状态；结束连接，执行约定清理；第二局问这些标记 | 新 LIE sessionId、状态归零、旧音频和事件被拒绝；三人均不带入旧标记；核实历史删除与记忆配置效果，连续重开 3 次 |
| 重连与切换竞态 | 回答中切换角色、断网再连、重复点出示或重开 | 无串音、无重复证据动作；旧会话不能更新新角色/新局；可继续或明确重新开始 |

测试期间先固定一个目标桌面 Chrome 版本，再按演示设备增加兼容验证。浏览器采集、权限拒绝、播放启动、采样重整、队列清空可先用本地音频与模拟网关验证；真实服务测试需接入资料就绪。

## 最少接入资料

- 允许用于开发的灵矽项目/账号与管理员访问方式，以及可用的测试额度和模型/音色类别。
- 平台 API 凭证的安全配置位置及权限范围；不在聊天或仓库文件中填写密钥。
- 测试智能体标识、设备标识/激活流程；虚拟设备与三角色会话的供应商接入说明（如有）。
- 云端 MCP 的配置入口、鉴权约定，以及可供平台访问的开发 HTTPS 地址或批准使用的隧道。
- 目标演示机器、浏览器与耳机/扬声器条件，便于统一延迟和回声测试基线。

## 阻塞与可独立推进的部分

真实语音链路、模型扮演质量、MCP 时序、三角色隔离和重开验收，均依赖测试账号/设备/额度与可访问的 MCP 服务；尚未通过不能作为已具备能力写进交付承诺。尤其虚拟设备和记忆范围若不满足，需要供应商给出支持方案。

可立即推进：案件与角色知识的数据结构、服务端游戏状态机、证据校验与结案规则、对话界面、网关适配接口、模拟音频/事件源、MCP 工具 schema 与本地测试、竞态与重开隔离。前端先对接 LIE 自有的会话事件协议，减少真实供应商协议调整对界面的影响。
