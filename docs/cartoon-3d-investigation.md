# 卡通人物 3D 化：能力调研与有界验证

2026-10-24。状态：研究候选，未批准正式接入，不替代已选 A 对话页或 2D 状态素材主线。

## 结论

浏览器技术上可以：静态站提供 JS 和模型，浏览器完成卡通渲染和动画，无需增加传统服务器或 DB；已有薄 Worker 和灵矽语音链路不必因此改变。本轮已经跑通独立静态构建的 WebGL 2 场景、真正几何体旋转、待机/聆听/说话状态，以及手动降级/恢复。

**尚未跑通的是把本项目现有插画变成风格保真、可变姿势、可做面部动画的正式 3D 人物。** 当前只有头至大腿、正面偏三分之四的 PNG，没有背面、多视图、网格、骨骼或口型。此实验用球体组合的原创占位人物，不是顾遥、沈禾或陈拓的成稿，也不是图转 3D 结果。3D 是否改善本产品的沉浸感，需要用符合风格的单人物样片判断，不能用“可旋转”替代视觉验收。

## 官方依据与边界

- [Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)：当前渲染器要求 WebGL 2，不应只检测浏览器名字；初始化失败时保留 2D。其 `info` 提供渲染计数，不能等同于显存或 GPU 耗时。
- [MeshToonMaterial](https://threejs.org/docs/pages/MeshToonMaterial.html) 支持卡通明暗，渐变纹理用最近邻过滤；[OutlineEffect](https://threejs.org/docs/pages/OutlineEffect.html) 提供轮廓描边。材质加描边仍不会自动复制现有插画的比例、线条取舍和表情。本轮用了 toon 材质，尚未做描边风格验收。
- [GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) 可在浏览器读取 glTF/GLB，包括动画等数据；[Blender glTF 导出手册](https://docs.blender.org/manual/en/3.6/addons/import_export/scene_gltf2.html) 说明骨骼蒙皮、形状键和变换动画的导出边界。这里引用可访问的 3.6 版本说明格式能力，具体生产应在选定 Blender 版本重验导出；没有把桌面软件中的任意 shader 或约束当作浏览器自动兼容。
- [Meshy Image to 3D](https://docs.meshy.ai/en/api/image-to-3d) 提供由图片生成网格的 API；存在该接口并不证明本项目的脸、服装和侧背面能稳定还原。没有上传或调用。
- [Meshy Rigging](https://docs.meshy.ai/en/api/rigging) 明确面向肢体结构清晰的标准双足人形；不能把半身裁切插画、模糊手脚或夸张比例视为已满足条件。自动身体骨架不代表具有可用的中文面部口型。
- [Meshy API 价格](https://docs.meshy.ai/en/api/pricing) 在本次查阅时：带 2K 纹理的标准图转 3D 为 30 credits，自动绑定 5 credits，动画每动作 3 credits；一次生成+绑定+三动作示例为 44 credits，未计重试、重拓扑或手工修复。API credits 与 Web 订阅不要混算，不据此承诺人民币总价。项目未购买资源或注册账号。
- [Meshy 商用说明](https://intercom.help/meshy/en/articles/16102098-can-i-use-meshy-assets-commercially) 区分付费与免费署名授权，并要求有上传参考图的使用权。若后续选择此类供应商，需要用户确认上传素材、账号、费用上限和当时条款；技术文档不构成项目已经取得模型/动画权利。

以上供应商只是已核查的可行路径例子，不是选型决定，也不承诺只靠 AI agent 可以完成专业角色资产制作。

## 资产生产的实际工作

1. 视觉负责人先确定一个角色的正/侧/背参考、身材比例、头发体积、描边和光照语言；原 PNG 不足以唯一确定不可见表面。
2. 手工建模，或生成粗模后修正：检查轮廓与身份、面数、UV、贴图、手指/衣物和拓扑。程序球体可验证运行时，但不是正式角色生产的替代品。
3. 身体骨架与蒙皮权重负责姿态；眨眼、眼神、眉毛和嘴部需要另做骨骼或 morph targets。自动绑定通常只解决其中一部分。
4. 做有限的 idle/listening/waiting/speaking 动作并导出 GLB；验证不同状态交叉过渡、手穿脸/衣服、镜头裁切。状态来自语音生命周期，不代表怀疑、说谎或罪责。
5. 浏览器调材质、灯光与描边，压缩模型/纹理、清理不使用数据，生成 2D poster/头像作为降级；验证切人时取消加载和释放 GPU 资源。
6. 真口型单独验收：仅 speaking 时循环张嘴是“说话动效”；音量驱动开合是近似同步；中文音素到 viseme 还需可靠时间轴与对应面部资产。本轮不假定灵矽提供该数据，不新增音频分析器，不修改已验证语音链路。

## 三条可讨论路径

| 路径 | 能提供什么 | 主要缺口 / 风险 | 主线影响 |
| --- | --- | --- | --- |
| 1. 先做一名风格保真的手工 3D 样片（推荐） | 真实几何、可控侧面、有限姿态；风格可由视觉负责人逐项验收 | 需要有建模/绑定能力的制作人或工具；先确认制作资源，不能保证现有 agent 自行达到生产质量 | 独立样片，2D 产品照常；一人通过再估算扩展 |
| 2. 单角色 AI 粗模 + 人工清理/绑定 | 有机会缩短粗模阶段，最终仍是真实 3D | 上传/付费/许可需确认；身份漂移、侧背面、拓扑与脸部质量待实测；重试会消耗额度 | 先设次数和预算上限，不批量生产三人 |
| 3. 保留 2D，完成状态图或有限 2D 骨骼动效 | 最接近已批准画风，资源和性能成本较低 | 不具备自由视角和真实 3D 体积；这是延期/对照方案，不称作 3D 化 | 对现主线改动最小，可作为样片比较基准 |

不建议把“换 3D 引擎”当成核心决策；主要不确定性是资产质量。Three.js 直接集成足以验证，不必为实验引入 Vue 3D 框架或完整游戏引擎。

## 现有契约与集成建议（待讨论）

- 保持案件 `appearanceId` 和现有故事/引擎不变；3D 属于可复用形象资源。头像和列表继续使用静态图，只有对话页的大人物区域可选 3D。
- 若样片通过，再在形象 manifest 提议一个可选的模型资源字段，如 `model3d: { src, camera, clips }`；确切结构应根据实际 GLB 的动画/面部能力定义，不先加一堆未使用字段。继续保留 `portrait` 和已实现状态图片作为回退。
- 一个独立渲染组件接收已解析资源与 `idle/listening/waiting/speaking`，不读取案件秘密，不接管麦克风、额度或语音连接；资源失败不应阻止语音与指认。
- Vue 的 [生命周期 hook](https://vuejs.org/api/composition-api-lifecycle.html) 可用于 mounted 后创建 canvas、unmounted 后停止帧循环并释放自有 geometry/material/texture/renderer。切人时销毁旧显示、处理迟到加载，不让每个人永久占一个 WebGL context。
- 控制一屏一个活动渲染器、像素比上限、离屏/页面隐藏停止渲染，尊重减少动态效果；完整产品仍需真机与音频并行负载测量。本轮不做这些正式集成。

## 本轮实际实验

路径：`spikes/cartoon-3d`，自带 package/lock，独立于根 workspace 依赖。Three.js 0.180.0、TypeScript 5.9.3、Vite 7.3.7（安装时发现旧版审计告警，已换修复版本，最终安装审计 0 vulnerabilities）。程序人物为 15 个球体网格、10,800 三角形、toon 材质，无贴图、外部模型、音频、密钥或远程 API。不是 2.5D 图片平移。

已实际执行：

- `npm run check`、`npm run build` 成功；产物只有 HTML + JS，可用任意静态文件服务器读取。
- Codex 内置浏览器加载构建后的 `dist`（Python 仅提供静态文件），待机显示成功，点击聆听出现倾头/抬臂；点击说话出现张嘴动效；旋转至 45° 显示侧面几何遮挡。
- 点击“模拟 3D 不可用”后 canvas 隐藏、静态占位出现；恢复后 3D 继续。这里只是降级路径模拟，不是一次真实 GPU 故障测试；没有证实所有 WebGL 初始化失败或恢复情形。
- Console warn/error 为空。截图 `spikes/cartoon-3d/preview.jpg` 来自上述内置浏览器，1280×897，真实 JPEG。
- 本机单窗口观测：冷开发加载首帧约 177.2 ms；构建静态页面一次加载首帧约 19.9 ms（均从模块执行开始，**不含下载**）；DPR 1，RAF 间隔均值约 6.1 ms / P95 约 6.5–6.8 ms。15 draw calls / 10,800 triangles。RAF 是调度间隔，不是 GPU 耗时/FPS 保证，单设备单样本不能外推低端设备或正式模型。
- JS 构建体积 476.63 kB，gzip 120.71 kB；额外正式 GLB/贴图下载尚未测量。

未验证：现有 PNG 转 3D、正式 GLB 导入与动画混合、真实骨骼/面部、语音音频同步、手机/低端机、长时显存、真实 context loss、完整 Vue 组件集成、线上 Worker 发布。隐藏页面跳过场景更新/渲染与 pagehide 资源清理已写入实验，但浏览器本轮未做专项性能验收。

## 下一步应请用户确认

建议先授权**一名角色的外观样片**，看正/侧面静态效果与两三个简单动作，再决定是否做正式 3D；不要立即把三名人物或全部素材迁移。

需要讨论：是否接受从“平面深蓝描边插画”到“有体积的卡通玩偶”带来的视觉变化；倾向手工资产还是允许有预算上限的 AI 辅助粗模；本轮目标是姿态/眨眼/近似说话动效，还是必须真实中文口型。后三者的工作量与资产要求不同。

不提供未经验证的日历交付承诺。可拆为：视觉多视图与样片审定 → 一名模型/绑定制作与修正 → 浏览器导入与性能回归 → 再估另外两名和正式集成。代码接入可独立估，资产阶段必须在实际制作能力与首件质量明确后估；当前实验不证明“再花几小时就能完成三角色”。

## 本地建模工具链：是否需要 Blender / MCP

- 浏览器渲染和本实验不需要安装 Blender。npm 依赖用于运行时验证，不包含建模软件；`three` 也不会自动把插画建成模型。
- 若后续选择在本地制作/修整模型、骨骼、面部 shape keys 或导出 GLB，则需要一个建模运行时。Blender 是可选方案；用户也可提供外部制作完成的 GLB，浏览器端不要求用哪款软件制作。
- Blender 本身提供 Python API `bpy`，并可用 CLI 后台执行脚本：`blender --background --python script.py`。脚本随 Blender 自带 Python 执行；不需要先安装第三方 MCP、插件或独立系统 Python 的 `bpy` 包。若没有 PATH 命令，可使用已安装应用中的可执行文件绝对路径。
- 可通过项目内受控脚本创建几何体、材质、骨骼、动画及导出；视觉复杂之处仍需查看渲染结果、逐步修正。能调用 API 不代表脚本能自动精确还原角色，尤其当前参考图缺少侧背面和可动画拓扑。
- root 对 PATH 和 /Applications 的常规检查未发现 Blender；这不是全盘扫描证明。本轮没有安装软件或连接第三方 Blender MCP。是否采用/安装留到用户选择资产方案时决定。

依据：[Blender CLI 参数](https://docs.blender.org/manual/en/latest/advanced/command_line/arguments.html)、[Blender Python API Quickstart](https://docs.blender.org/api/current/info_quickstart.html)。具体命令与 API 在实际选定版本安装后再校验，不提前承诺版本兼容。
