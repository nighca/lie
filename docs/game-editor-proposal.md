## 产品范围与现有基础

目标是让用户创作同一审讯玩法的故事，预览，再把可玩的内容交给其他人。不等于新玩法设计器、规则 DSL、自动生成剧本、多人协作编辑或中心游戏商店。

当前 `packages/game-core/src/content.ts` 的实际 `GameDefinition` 包含：

| 内容 | 现有约束 |
| --- | --- |
| `id`、`title`、`background` | 非空文本；公共背景为纯文本 |
| `interrogationLimitSeconds` | 正安全整数，跨全局人物累计的语音启用额度；不是供应商费用上限 |
| `characters` | 至少一人；人数不是固定三人。作者体验是否额外建议最少两人需要讨论，不改变引擎事实 |
| 每人 `id`、`name`、`profile`、`appearanceId` | ID 唯一；姓名/完整角色设定为纯文本；形象 ID 可空 |
| `ending.culpritId`、`ending.reveal` | 一个答案，必须引用现有人物；结局说明非空 |

复用现有 `validateGame` 做机器可判断的结构校验、使用通用引擎试局；不自动证明剧情无矛盾、答案唯一可推、角色不会泄露或模型不编造。当前校验器也没有文件体积、总文本量、字段长度、人数上限或导入格式版本，这些是面向不受信任外部包时待补充的边界，不能说现在已具备完整导入支持。

## 三种创作—预览—分享动线

共同起点（拟议）：进入创作 → 填标题/公共背景 → 增删人物、写各自设定并选预置形象 → 指定唯一正确人物、填结局和时间 → 校验 → 用同一份内容快照新开试玩。预览切回编辑不会修改正在进行的那局；再次试玩新开局。作者已知道答案，预览用于检查流程和角色回应，不代表盲测难度验收。

### A. JSON 文件包：建议首个可实现阶段

作者完成后导出一个仅含故事和预置形象引用的 JSON 文件；用聊天附件、邮件或其他现有渠道自行发送。收件人打开 LIE，选本地文件，校验后先看标题/公共背景和“来自导入内容”的来源提示，再主动开始游戏。打开文件不自动申请麦克风，也不直接创建供应商连接。

文件导出是作者的可携带快照。修改后重发新文件；已经发出的副本不能统一更新、撤回或禁止再分发。接收方只在当前浏览器处理文件，是否保存本地游戏库另定。不会自动出现在项目的官方案件列表。

优点是无服务器端内容存储、不受链接长度限制、便于备份和故障定位。缺点是分享有“先打开应用再导入”一步；文件关联自动双击启动不是 Web 首版的默认能力，也不承诺不同设备自动同步。

### B. 压缩内容装进 URL fragment：小文本的便捷选项

作者完成后生成 `https://我们的站点/...#...` 形式的内容快照链接（具体路由/编码未定）。浏览器在客户端解码、校验，展示接案页，收件人主动开局；不用作者先找托管空间。推荐始终保留文件导出回退。

fragment 不会随页面 HTTP 请求发给站点服务器，但页面脚本仍能读取它，聊天平台、浏览器历史/同步及持有链接的人仍可能接触完整载荷；**压缩和 Base64 都不是加密**。本项目已接受浏览器可见所有角色设定与真相，此方案不额外保证防剧透或内容机密。[URI fragment](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment)、[RFC 3986 §3.5](https://www.rfc-editor.org/rfc/rfc3986#section-3.5)

长度必须按完整编码链接计算。没有一个适用于所有浏览器、聊天客户端、二维码和剪贴板的统一安全最大值；不能把“浏览器能打开”当成“各渠道完整传递”。尤其不要把 [RFC 9110 §4.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-4.1) 对 HTTP URI 的 8000 octets 支持建议误当 fragment 链接的端到端保障。

本轮只读测量现有首案：源 JSON 9,280 UTF-8 bytes，移除格式空白后 9,110 bytes，Python 标准库 gzip 后 4,307 bytes，Base64URL 去填充后 5,743 字符；尚未加站点、版本和编码标记。这只是一个文本样本的尺寸估算，不是浏览器压缩互操作或聊天渠道测试，不能承诺所有故事同压缩率。编码后二进制通常约有 4/3 的 Base64 长度开销。图片/音频/GLB 不适合塞进这条链接。

[Compression Standard](https://compression.spec.whatwg.org/) 提供 gzip/deflate 等流式 API，允许浏览器内处理；实际目标浏览器与解压失败/超量输出仍需未来验证。初步可设“便捷链接建议不超过 8,000 字符，超过则只提供文件”，但这个数值仅为待测试的产品门槛，不是标准，也不能保证低于它所有渠道都可用。

链接是不可变快照：修改生成新链接，旧链接依然带旧内容；没有中心映射服务便不能靠删一条记录撤回。第三方短链服务会引入另一个存储/供应商依赖，不在“无服务端内容存储”方案中默认使用。

### C. 作者自行静态托管 JSON：可更新的链接

作者导出文件，自己放到可公开读取的 HTTPS 静态站/对象存储，分享“LIE 播放器入口 + 内容 URL”。播放器在浏览器直接 fetch，校验并让用户确认开始。内容仍由作者托管，项目不建设内容数据库或账号。

外站需允许播放器来源的 CORS，否则浏览器能导航看到 JSON 不代表 JS 能读取；`no-cors` 的不透明响应不能作为可读 JSON 变通。应直接告知下载文件后走 A，不把薄 Worker 改为任意 URL 代理。[Fetch CORS protocol](https://fetch.spec.whatwg.org/#http-cors-protocol)

作者可在同一 URL 更新/删除未来访问的内容，但缓存和已下载副本无法召回；一局开始时取快照，不在会话中热换答案。要精确分享固定版本，应给文件 URL 带实际版本路径/内容摘要；单纯查询参数不等于完整性保证。稳定 URL 指向可变内容与固定快照的取舍要向作者说清楚。

需要外部请求次数/超时/响应大小/重定向后的实际来源约束；只接收 HTTPS JSON，不支持凭据 URL、私有带密钥链接或任意可执行页面。远程获取会向托管方暴露访问者的网络请求信息，需在用户主动选择/打开内容时发生，不能后台扫描一批 URL。没有本项目的代理 SSRF，但客户端请求外部资源也有隐私/网络边界，具体来源策略待选。

此方案作者操作门槛最高，静态托管本身**仍是外部持久存储**；不能称作“完全无存储”。本轮不选托管商、不替作者创建账号或部署。

| 比较 | A 文件 | B fragment 快照 | C 自有静态托管 |
| --- | --- | --- | --- |
| 收件人 | 导入文件后开局 | 点链接后开局 | 点播放器链接后拉取内容 |
| 项目服务端内容存储 | 无 | 无 | 无；作者自己的站点有存储 |
| 更新/撤回 | 新文件；副本不可撤回 | 新链接；旧链接不可撤回 | 能改变后续获取，无法撤回缓存/副本 |
| 体积边界 | 应用设限 | 应用设限 + 渠道长度 | 应用设限 + 托管/CORS |
| 主要摩擦 | 文件传递/导入 | 长链接、渠道截断 | 作者有托管与配置能力 |

## 形象与自传素材分阶段

建议最小阶段只有纯文本 + 引用项目预置的 `appearanceId`。编辑器展示可选库和缩略图；声音、状态图沿形象配置走，不允许内容包自带灵矽 voice ID、平台管理凭据或任意音频接口。未知形象 ID 是报错还是使用现有头像/默认立绘回退，应明确区分“可玩但显示替代”和“导入失败”，不能悄悄错配另一个角色。是否允许多人物共用一个形象由用户决定，不把 ID 唯一性误加为引擎约束。

自传头像/状态图/声音/3D 是另一档范围：要定义打包目录/清单、MIME 与真实格式/解码尺寸限制、相对路径和重名处理、缺图回退、压缩包展开体积与路径穿越防护、资源释放、许可证和作者署名；远程素材还有 CORS、跟踪、下线和内容变更问题。JSON 中 Base64 图片会膨胀并抬高内存峰值。音色克隆与模型上传不属于一个“选图片”按钮的成本。不建议首阶段默认接受 SVG/HTML、脚本化动画、任意 3D 资源或自定义 Worker URL。

本地生成的 `blob:` URL 只引用浏览器持有的对象，不是可跨设备分享的公网资源；应在资源不再使用时 revoke，不能导出一个临时 URL 让别人期待能读到图片。[createObjectURL](https://developer.mozilla.org/en-US/docs/Web/API/URL/createObjectURL_static)

## 版本、校验与安全边界

建议未来把分享容器版本与故事本体分开，最小封装如格式标记 + `formatVersion: 1` + 现有 `GameDefinition`。这是提案，不把新版本字段直接改进引擎。读取明确支持的版本，再规范化到现契约；不支持的新版本应说明升级需求，不能猜测字段含义或静默丢掉结局。可选作者名/简介/作品修订号等发布元信息必须有实际用途才加，不先建设出版系统。

外部输入需有编码前/压缩前/解压后边界：例如仅文本包的**候选**上限为 128 KiB 未压缩 UTF-8 总量，另设字段/人数上限以匹配模型上下文；具体数值需在用户批准开始后用实际内容与灵矽能力测试，不作为当前内容规范。本轮没有实现解析器。解压流应累计检查输出而不是先无界解压再检查。文件、fragment、外部 URL 的任何传输路径都必须进入同一结构校验，不靠文件扩展名或链接来源跳过检查。

当前核心校验明确逐字段构造新对象；未来导入也保持这种方式，不把任意 JSON 对象深合并到全局配置。只把故事作为文本显示，不编译成 Vue 模板，不用 `v-html` 渲染作者字段；不解释脚本、Markdown HTML、CSS 或规则表达式。Vue 默认文本转义有助于降低 XSS 风险，但不能为主动插入 HTML 或不安全资源 URL 背书。[Vue security](https://vuejs.org/guide/best-practices/security.html)

故事设定可以含 prompt injection，但它应始终是角色内容，不是给应用/Worker 的指令。不能通过内容包配置工具执行、指定其他人物上下文、改变固定胜负判断、上游地址或供应商凭据。结构校验无法判断内容是否侵权、诽谤或令人不适；如未来做公开发现/托管/推荐，内容治理是新的产品责任，不能因前端可读就略去。

## 草稿、发现和身份的取舍

最低范围可只在本页内存编辑并要求用户导出备份。若要求自动存草稿，可用 IndexedDB 等浏览器本地存储，但它仍是存储，不是“无数据状态”；配额、隐私模式、用户清理和回收会影响留存，应提示及时导出。不能把本地成功保存当云备份或跨设备同步。[浏览器配额与回收](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

不建账号/中心内容存储意味着：没有作者身份认证、统一作品管理、跨设备同步、中心搜索/发现、统一撤回或访问统计。显示的作者署名只是自报，不能标成平台认证。玩家可把文件复制改名/再分享；本轮不引入签名 PKI 或 DRM。官方案件列表和本地导入的作品应区分来源，导入不能覆写官方内容或污染已有 session。

系统分享面板 `navigator.share` 可作为未来增强，但受浏览器支持、用户触发和可分享数据类型限制，不应是唯一导出路径；下载与复制链接的具体 fallback 需要在实现阶段测试。[Navigator.share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)

## 真实语音与费用是独立决策

导入合法游戏不等于取得无限语音授权。预览需要区分结构/页面检查与真实灵矽试玩：真语音始终使用薄网关保管平台凭据，传当前角色文本，不把 API key 写入文件/链接。浏览器已有全故事的事实不意味着应把其他角色设定与结局一并发给当前角色。

“谁的账号和预算承担陌生作者与所有收件人的语音”必须单独讨论：沿用项目额度、每人自行部署自己的网关，或其他正式方案各有产品摩擦和限额要求。作者的 `interrogationLimitSeconds` 只是玩法时间，客户端可修改，不是全站费用防线。本案**不实现访问/限额控制，不默认开放任意作品共享我们的付费额度**；当前线上临时预览授权也不是未来公众创作平台的预算批准。

R2/KV/Durable Objects 等可用于中心作品/短链接/计数，但都会引入云端状态、部署/权限/治理和费用；即使不叫传统 DB，也不满足“项目服务端不存内容”的同一约束。只有用户明确需要稳定短链接、统一更新撤回或中心发现并接受新边界时，再独立论证。

## 推荐最小阶段及后续决策

**推荐，未定案：未来获准启动后先做 A，文本编辑 + 预置形象 + 同引擎预览 + JSON 导出/导入。** 不要求作者找托管空间，也不让一条长链接的渠道兼容性成为初次创作的阻塞。是否补 B 的便捷快照或 C 的高级托管导入，等第一阶段反馈后再选。三者不需要同时交付。

开始前需要用户确认：

1. 是否现在正式启动，以及首阶段是否按 A 的范围；当前仍为延后。
2. 是否必须“一条链接就玩”，若是，能否接受长链接的体积/不可撤回边界，或作者自托管门槛。
3. 首阶段是否只用预置形象、是否需要自动本地草稿；自传素材和账号/中心发现是否继续后置。
4. 真语音分享者/玩家的付费与访问范围；不把这个决定塞进文件格式。

未来实现的验收应覆盖导出→另浏览器导入→正确/错误指认终局→重开，以及不同人数、未知版本、缺失/重复 ID、无效答案、额度/字段越界、坏编码/解压超量、HTML 文本安全、未知形象与旧局隔离。故事质量另做真人盲测和有预算边界的真实 AI/语音验证；fake provider 只能验流程。文件传输渠道/fragment 长度/CORS 均应实际验证后才写成支持范围。

本轮完成的是实际契约审阅、官方资料与三路径比较，以及现有首案的只读体积测量。没有对任何拟议动线做浏览器原型或端到端验收。后续即使出现空闲容量，也不能越过本文首段的用户启动门槛。
