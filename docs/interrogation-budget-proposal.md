# 每局审问总时限提案

状态：2026-10-24 用户已批准 A“语音启用时间”和本文到期行为，并确认首案8分钟；实现与验收进行中。下文保留方案比较作为决策依据，B未选用。连续语音独立真人实验已由用户确认多轮与打断体验可用。

已知意图：每个游戏配置自己的额度，同一局跨所有人物累计，切人不重置。它限制语音询问，不应直接等同于从接案开始计算的整局墙钟时间，也与网关 WebSocket 的 3 分钟连接上限无关。

## 两种计时口径

| | A：语音启用时间（建议先采用） | B：实际发声时间 |
| --- | --- | --- |
| 计入 | 收音实际启动后，连续语音处于启用状态的时间；包括玩家说话、开着收音思考的沉默、等待模型和角色播音 | 玩家被可靠识别为正在发声的区间，以及本地实际播放角色声音的区间；两者重叠取并集，不重复扣时 |
| 不计 | 接案阅读、建连/权限等待，以及停止语音后的切人、回看、指认、隐藏页面、断线等待与手动恢复前的时间 | 另排除收音中的沉默、模型等待、仅缓冲而尚未播放的音频；其余暂停边界同 A |
| 连续语音 | 开启一次后连续累计，直到停止；切人/指认/隐藏结束收音，断线后手动恢复，均不悄悄重启计时 | 不能以“麦克风开着”代替“玩家正在说话”；需要可信的语音起止边界 |
| 取舍 | 实现和解释简单，现有生命周期可承接；但用户沉默和供应商延迟也消耗额度，必须明确告知 | 更贴近“双方实际说了多久”，但当前事件只有 STT 文本、TTS 和音频，尚不能准确测出玩家发声区间；需额外验证 VAD/时间信息，不能按字数或转写到达时间猜测 |

建议先采用 A，并在界面称为“剩余询问时间”，注明“语音开启时计时，停止后暂停”。这不是普通整局倒计时：未开启语音、连接失败或停止后回看历史都不会扣时；如果只是查看历史而没有停止语音，仍按启用状态计时。若产品希望不受沉默和服务延迟影响，应选 B 并先补齐实测依据，而不是暗中把 A 宣传为精确发声时长。

## 到期行为建议

时间归零后立即停止收音、播放及当前连接，提交已经显示的转写并标记中断，沿用旧连接事件丢弃规则。提示“询问时间已用完”，打开最终指认；不自动判负、不自动选择人物或泄露答案。

玩家仍可关闭弹层回看各人的历史、再打开指认，或主动结束/重开；不能再开始语音。选错仍可回看并重新指认，不增加惩罚或次数限制，也不补回时间。这是在额度用尽后保留现有指认规则的建议，须用户确认。重开回到接案，按新局重新获得完整额度；切人、关闭指认或断线重连都不恢复额度。

## 内容与模块边界

| 位置 | 最小改动提案 |
| --- | --- |
| 内容 A | 增加 `interrogationLimitSeconds`，建议为必填正整数元数据；由每个游戏作者设置，校验器只检查数值合法性。实施时同步内容与测试包，不预设无限模式或全局默认分钟数 |
| 规则 B | 单局持有累计已用毫秒数，起始为 0；纯函数接收外部算出的时间增量，累计并封顶。额度用尽是派生能力限制，不必新增游戏阶段；仍允许现有指认/结束/重开。无 timer、设备或 Vue 依赖 |
| 编排 D | 按选定口径采集时间区间并交给 B；启用/停止只结算一次，绑定本局与连接 epoch。A 在收音真正启动时开始，停止、切人、指认、隐藏、断线、结束或重开前结算。B 则需可信发声/实际播放区间，不能复用 A 的开启时长冒充 |
| 语音 E | 提供实际启动、停止、关闭及播放生命周期；连续语音验证成功后再落实事件契约。不在供应商保存游戏计时，也不让模型修改额度 |
| 界面 F | 只展示 D 的剩余时间与是否还能询问；到期阻止重新开启语音，保留只读转写和 UI 指认。不自己扣秒或判断超时，不新增计时开关 |

D 使用可注入的单调时钟（浏览器可用 `performance.now()`），与现有对话记录的日期时间分开。根据真实时间差计算，而不是假定每次 interval 都准时扣一秒；刷新展示的 tick 不改变事实。即便回调延迟，下一次回调或操作前也先核对是否到期，剩余数值不变负。页面隐藏时按已批准生命周期停止并结算，返回后等待用户手动恢复。当前内存局刷新即新局的规则不变，不新增数据库、持久化或防作弊设施。

实现时复用统一停止入口，先结算、停止旧设备并保存可见文字，再切角色/局；到期回调也要验证局和 epoch。规则与展示共用一份已用量，不把每个人的时间再维护成另一套额度。B 方案若尚无可靠事件，不实现近似计时后宣称精确。

## 自动化与真实验证

- 纯规则：不同内容额度、非法数值、累计与封顶、重开归零、切人不重置；指认不因到期自动判负。
- D 使用 fake 时钟/设备：建连和权限等待不扣；按口径累计；停止、切人、指认、隐藏、断线/恢复不漏算或重复扣；两局与迟到回调隔离。
- 边界：收音权限迟到但已切人时不启动计时；计时回调被延迟时仍按时间差正确到期；到期和切人/回答完成同时发生只停止一次，旧音频不继续播放。
- F：剩余时间展示、归零后语音不可重启、指认仍可用、选错后不返还额度、重开恢复；timer 不每秒抢占屏幕阅读器播报。
- 真实验证另做：连续收音/等待/播放的起止与隐藏/断线资源停止是否匹配。若选 B，还要实测 VAD 起止和本地播放时间，覆盖静音、回声与双方重叠，不能以 fake 通过替代。

## 交由主代理统一确认的两个问题

1. 额度采用 A“语音启用时间（包括沉默和等待）”，还是 B“实际发声/播放时间（排除沉默与等待）”？建议 A；两者都跨人物累计，不等同整局墙钟时间。
2. 是否采用上述到期行为：停止语音、保留历史并进入指认，允许回看/再次指认/重开，但不再询问？建议采用；不额外引入超时即失败或自动揭晓。
