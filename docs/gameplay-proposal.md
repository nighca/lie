# LIE 首版玩法与内容验收

更新：2026-10-23。**本页同步已经确认的玩法，首案《空盒里的纪念章》已选定。** 正式模块、原型流程与中文 B 视觉方向已获用户批准；具体案件见 [内容提案](case-options.md)。旧版较重的调查流程由本页当前语音玩法替代。

## 一局怎么玩

| 阶段 | 玩家操作 | 游戏反馈 |
| --- | --- | --- |
| 开场 | 阅读简短公共背景，查看三名人物，点击开始 | 进入语音审讯；公共背景不泄露固定答案 |
| 审讯 | 用麦克风自由组织问题、追问或复述其他人的说法 | 当前人物自然回应；展示真实收音/等待/说话状态，可查看只读转写 |
| 切人 | 点击其他人物，再继续语音问话 | 停止旧音频，载入该人物自己的本局历史，避免把前一个人的设定或回答带给他 |
| 指认 | 点击指认入口，明确选择一个嫌疑人 | 浏览器按固定责任人判断；不要求理由输入，不让模型裁判 |
| 选错 | 阅读错误反馈，再返回审讯 | 不结束调查，不增加惩罚或次数限制 |
| 选对 | 阅读真相揭晓，选择重新开始 | 清晰区分各人的隐瞒与实际取走行为；新局回到开场并清空历史 |
| 主动结束 | 点击结束当前调查 | 停止语音并结束本局；不把结束误当成指认成功，也不凭空补写角色认罪 |

玩家与人物之间只有自由语音。转写是只读回顾，不提供文字聊天兜底；获批准原型中的模拟发言仅用于演示交互，不能当作真实语音验收。麦克风或连接失败时应显示可操作错误，而不是悄悄改为文本聊天。

## 玩法中的推理与程序判断

玩家的乐趣来自听清具体经历、区分亲历与推测、发现回避、交换问序并判断谁实际做了那件事。角色可以隐瞒自己的小过失，表达可以变化，但不能随意改写设定、增加人物或把没见过的事说成亲见。

程序只管理单局、当前人物、逐人对话历史和最终选择。最终比较 `characterId` 与固定 `ending.culpritId`；不评分玩家理由、不检测指定关键词、不要求嫌疑人承认、不设隐藏的内容解锁。玩家直接猜中也会成功，这与按钮指认的已确认范围一致；不能宣传为程序验证了完整推理。

故事作者只写公共背景、每人完整 `profile` 与固定结局。人物面对具体追问时如何回避、何时把知道的事讲清，写在自然语言设定中。工具用来提供正确角色上下文，不代替角色认罪或增加作者要配置的剧情机关。

## 一份首案内容怎样算可评审

- 公共背景足以理解目标、人物范围和场景边界；真相不依赖结算时才补出的第四人或新机制。
- 三个人都有值得询问的亲历或隐瞒；不能把“甲知道全部真相”写进作者分析，却不给玩家自然问到的信息。
- 不同问序和同义问题仍可获得关键亲历；不要求念出时间数字、完整姓名或特定句式。
- 仅用角色已有知识就能形成合理、唯一的责任人判断；隐藏动机或藏处可以留到揭晓，但不得用它们在事后才排除另一人。
- 角色初始回避与后来说明保持一致；秘密不是“每个人都随时任意编造”，不能因模型无限嘴硬让案件不可解。
- 明确区分固定故事内的可解性与对全部口头证词的信任问题；当前玩法不提供独立于人物发言的事实验证系统。

## 验证层次

| 层次 | 检查什么 | 不能据此声称什么 |
| --- | --- | --- |
| 静态内容校验 | 必填文本、三人/任意角色集合、ID 唯一、`culpritId` 引用、形象引用字段的形状 | 不能证明故事有趣、真实模型遵守设定或真相逻辑唯一 |
| 作者人工模拟 | 按每人的亲历与口径跑不同问序，列替代解释与对话可获得内容 | 不等于灵矽真实问答或陌生玩家能独立完成 |
| 真实角色评估 | 普通追问能得到信息、不越界、不过早揭晓、不跨人物/跨局带入记忆 | 不等于真实麦克风、播放和打断链路都可用 |
| 真实语音与盲测 | 收音/识别/首音/播放/打断、切人和重开；陌生玩家是否理解目标、能否得出合理结论 | 未测得单局时长前，不承诺原草稿3–6分钟 |

首轮试玩优先记录：第一句通常问什么、哪位人物容易无话可问、哪里听不懂、会不会把“说谎”直接当“做了这件事”、是否能回忆交接顺序。根据实际问题先改内容和措辞，不自行增加产品范围。
