# 持久化分享链接设计

状态：用户已表示除本次修订点外无异议，整体方向获认可；单项上限提高到1 MiB为本次修订建议，具体数值尚未确认。未授权实现、创建云资源或上线。专项 worktree 基线为 `a8be75823ceb67966390b5534d725a3a8bf1505b`。

## 已确认方向（2026-11-01）

- 目标是解决完整案件装入 URL 所产生的长度限制，保持一键分享，不要求作者增加字段或自行托管。
- 用户确认可先按长期有效设计。默认不设置自动过期；这不等于已承诺永久保存或不可因运营、安全等原因移除。相关政策尚待讨论。
- 用户接受修改案件后生成新链接，并提出使用内容 hash 关联 URL 与案件，使确定的链接对应确定的游戏内容。链接指向不可变内容快照，不覆盖为新内容。
- 用户确认哈希前统一内容序列化，避免 JSON 字段排列不同造成不同链接；认为打开时重新校验内容哈希属于过度设计，移除该步骤。读取时仍沿用案件结构校验。
- 用户要求只在写入端执行体积限制，不增加服务端或前端的读取体积检查；暂不加IP限流和停写开关，避免共享出口误限与过度防御。
- 不因此扩大为账号、云同步、作品管理、公开发现或上传素材。沿用浏览器运行游戏、平台凭据保持服务端的边界。

## 内容身份与不变量

分享时校验案件，产生确定的内容表示，计算内容哈希，再持久化该快照；URL 携带内容标识。接收方取回后检查内容契约，再进入现有游戏流程，不额外重新计算和比对内容哈希。同一份规范化内容可复用同一链接，内容改变则得到不同标识。

哈希应覆盖完整案件，包括案件和人物 ID、标题、简介、背景、角色顺序与设定、预设形象 ID、时限、答案和结局。不对 gzip 输出直接建立内容身份。哈希表示内容身份，不是加密、作者身份认证或访问权限。

默认不过期省去到期判断、续期和自动清理流程，但累计存储量、滥用写入、服务停止及必要下架仍需处理。不可变快照保证链接不会被替换成另一份案件，不保证链接永远可访问；已下载副本也不能通过服务端删除召回。预设素材或未来引擎变化可能影响呈现，固定内容不等于所有未来运行效果都完全相同。

## 待讨论与研究

用户于2026-11-01新增以下四点，均为设计议题，不构成实现或资源创建授权：

1. **单项体积上限。** 读写能力应考虑单项大小限制以避免滥用。用户后续明确限制只做在写入逻辑，且新存储上限应明显高于现有128 KiB解压预算；具体修订建议见下文。
2. **Cloudflare 现成能力的薄封装。** 比较适合“内容标识→不可变案件快照”的现成存储，设计最小读写接口及前端调用方式。是否复用现有 Worker、存储绑定、上传时由哪一端生成标识，以及刚写入后能否立即读取均需明确；后续整体方案已选定建议R2，用户表示除此轮修改外无异议；不创建资源，不把简单案件分享扩成通用存储平台。
3. **本地开发的存储去向。** 比较本地持久化模拟与连接在线开发存储的利弊，明确分享链接在本地/线上是否可互开、环境隔离及离线开发体验。后续认可默认本地模拟的方向，并询问是否由Cloudflare工具提供，见下文说明；不向生产存储写入测试数据。
4. **现有 gzip＋Base64URL fragment 路径是否保留。** 分开讨论已分享链接的读取兼容和今后是否继续生成这类链接。评估离线/服务不可用时是否确有保留生成路径的需求，以及双路径的交互和维护成本；不自动增加回退或双模式入口，也不把存储请求失败静默改成长链接。

其余待讨论事项：

- 无账号、无额外限流的首版以写入大小和案件结构校验为边界，不把去重称为写入保护。
- 删除/撤回是否属于首版范围，及必要下架的操作边界。
- 旧 fragment 链接兼容、网络失败与内容不存在的用户体验。

## 首版整体设计（按用户反馈修订）

复用现有同源 Worker，绑定一个**私有 R2 Standard 桶**，增加案件快照的两个接口。不开放桶的公网域名，不给浏览器存储管理凭据，不引入账号、数据库表、公开列表、通用文件上传或第二套后端部署。

这是对已批准的“薄 Worker 仅传输 provider”职责的明确扩展，本次整体设计反馈除列明修改外无异议；浏览器承载游戏会话与判案的边界保持不变。桶私有只表示不能绕过 Worker 直接访问桶，不表示持链接的案件内容私密。

```text
作者点击分享 → 同源 Worker 校验、规范化、算 hash → 私有 R2 保存 JSON
            ← 返回内容 ID → 前端展示 /play?share=v1.<hash>
玩家打开链接 → 同源 Worker 读取对应 JSON → 前端校验 → 现有接案/游戏流程
```

存储服务负责分享内容，不接管游戏会话、判案或语音额度。新鲜链接需立即可读是选择存储的重要条件；不把最终一致性带来的暂时找不到内容交给用户重试。具体官方依据与备选比较见 [研究记录](share-storage-research.md)。

### 接口和内容标识

| 操作 | 建议协议 | 结果 |
| --- | --- | --- |
| 创建分享 | `POST /api/shared-games/v1`，`application/json`，body 为完整 `GameDefinition` | `200 { "id": "<22字符Base64URL>" }`；新存储和重复分享使用相同成功语义 |
| 读取分享 | `GET /api/shared-games/v1/<22字符Base64URL>` | `200`，规范化案件 JSON；不返回存储配置或作者网络信息 |
| 玩家入口 | `/play?share=v1.<22字符Base64URL>` | 前端读取一次快照，之后同现有游戏一样在浏览器运行 |

服务端决定ID，不接受客户端指定存储key；前端用当前origin组装链接。用户要求比64字符十六进制更短，修订建议为：SHA-256取前16 bytes（128 bits），用无填充Base64URL编码，得到固定22字符的内容标识。按 `https://lie.agency/play?share=v1.<id>` 格式，完整URL为55字符。此具体截断长度是本轮建议，尚未获得精确数值确认。

在哈希近似均匀分布下，n份不同内容的任意碰撞概率约为n(n−1)/(2×2^128)；100万份约1.47×10^-27，10亿份约1.47×10^-21。首版接受这一可忽略概率，不增加碰撞映射表、重试分配或额外读取校验。不将短ID用于身份认证或保密。

以固定 v1 字段投影构造对象后 `JSON.stringify`，对其UTF-8 bytes计算SHA-256，取前16 bytes并编码为上述内容ID，存为 `games/v1/<hash>.json`。固定投影沿用当前 `validateGame` 的字段语义：对象字段顺序固定；人物数组不排序；正文、空白、换行不改写；`appearanceId` 缺失归一为 null；未知字段不进入规范化快照；可选 summary 省略与空字符串仍是不同数据。单独固定此 v1 序列化约定，不能让未来调整校验器输出顺序悄悄改变 v1 协议。不需要通用 JSON canonicalization 库。

保留 `game.id` 和人物 ID，不用 hash 替换它们，不重编号。当前草稿和再创作会生成 UUID，因此承诺是同一份规范化数据有相同链接，**不是**两份文字相同但 ID 不同的草稿必定去重；这也避免改变现有引擎内容身份语义。

服务端每次直接 put 同一 key、同一规范化 bytes 即可，不增加 HEAD 预查、条件创建、锁或去重数据库。客户端不能用旧 ID 上传另一份内容；服务器重算 ID 决定 key。重复分享可能再次产生写操作费，但不创建另一份内容对象。读取时不重算 hash。

`v1` 是协议约定，不是作者需要操作的作品版本管理。固定的是案件数据；预设图片、动画、引擎和模型的未来变化不由此冻结，不新增永久兼容所有旧应用的承诺。

### 大小与输入边界

用户认为128 KiB提升不足，修订建议为 **1 MiB（1,048,576 bytes，原上限的8倍）** 上限；此具体数值待确认，分别约束请求体和规范化后存储内容；以 UTF-8 bytes 计，不按字符数或 gzip 压缩后大小计。前端先检查并提示，服务端是最终裁决者。

- `Content-Length` 超限可提前返回，但不能信任其存在或正确性；流式累计实际读取量，越界立即停止，不能先完整 `request.json()` 再判大小。
- 不接受请求体 gzip 等 Content-Encoding，不接受二进制/素材/外链资源。只存通过现有 `validateGame` 的案件字段，不是任意 JSON 存储。
- POST 同时校验非空形象 ID 属于当前预设目录；复用 `design/character-presets/manifest.json` 的权威 ID 集合，不在 gateway 手写第二份名单或将图片/动画导入后端。沿用 core 对 null 的既有语义。旧内容读取仍由 web 显示当前不可用预设的明确错误。
- GET直接返回已通过写入校验的存储内容，不检查对象size或累计响应bytes；前端正常解析JSON并进行案件及现有预设校验，不重复施加体积上限。
- 保持可变人数，不新增硬编码三人或修改通用游戏规则。暂不另设任意标题字数、人物数或时长上限；若现有 UI/语音实测显示独立风险，再按具体证据讨论。
- 1 MiB只规定新存储写入预算，不修改旧fragment的128 KiB解压限制，也不代表provider对单个角色上下文容量的保证。当前URL路径还有16,000字符的独立限制；改用存储同时消除该限制。

### 写入边界与费用

写入保留同源Origin检查、JSON Content-Type、实际请求体大小上限和案件结构校验，不开放跨域写入。Origin不是身份认证，非浏览器客户端可以仿造。读取也不开放跨域CORS，但持有URL的人仍能下载完整案件。

按用户明确反馈，首版不加IP限流、Rate Limiting binding、全局请求计数或停写配置开关，也不因此引入DO、Turnstile、账号、邀请码。共享出口不会因本功能的IP计数而被误限。初版限流/开关建议已撤销，原提案保留在Git历史，不能在实施时恢复。

单项限制不构成请求频率或总费用硬上限。费用仍包含累计存储、R2读写操作和Worker请求；使用平台现成指标观察即可，不为此开发额外控制系统。不记录正文、答案、完整IP、请求body或鉴权头。缺失绑定或存储失败正常返回错误，不返回未经确认保存的链接。

### 本地开发与环境隔离

建议**默认用本地持久化 R2 模拟，不访问在线生产桶**。沿现有 gateway 的 `remoteBindings:false` 和 cf 开发流程，web 增加同源 `/api/shared-games` 代理至已有 gateway；测试使用 fake 或本地 binding。这是Cloudflare本地开发工具链提供的R2模拟能力（Miniflare），不是项目自己实现一套R2模拟；我们只做binding、代理和本地持久化配置。参见[官方本地binding支持表](https://developers.cloudflare.com/workers/local-development/bindings-per-env/)。具体cf beta配置写法和状态目录需实施时核对已锁定版本。

本地状态保存在不入 Git 的开发缓存内，跨重启保留不等于云端保存；不同 worktree 默认隔离，不能把 main 8787/8788 的在线语音配置授权当成存储生产写入许可。本专项不启动服务、不更改既有消费者/端口。

本地生成当前 origin 的链接，只在该开发环境可读；仅将域名改成线上不能凭 hash 让线上拥有数据。前端本地开发仍可打开 fragment 旧链接，但生产短链接内容不会自动复制到本地。若需要直接在本地浏览器查看生产分享，直接打开生产页面；不默认加入线上读/本地写的混合路由。

另用隔离在线开发桶做真实部署验收，检查分享后立刻跨客户端读取及绑定行为。此步骤需要后续资源/环境许可，不在本轮执行；不能以本地模拟测试替代云端行为验证。不开放浏览器直接访问 R2，也不增加生产桶通用 CORS。

### 旧 fragment 与失败体验

建议**保留旧链接读取，停止日常生成旧式链接**。旧 `/play#game=...` 原样走现有解码和限额；新分享只走持久化存储。首版不提供双模式选择，不把上传失败静默回退为长链接，也不自动迁移/上传用户刚打开的旧链接。旧内容只有作者主动点击分享才保存到云端。

新、旧标识同时出现应报“链接格式不正确”，不偷偷选择其一；未知版本或非法 hash 在本地拒绝，不发无效存储查询。旧路径的 16,000 字符与解压上限保留；新路径只接受固定格式的内容标识，不受旧载荷限额控制。

分享只在点击按钮时上传，不在输入、保存本地草稿或试玩时上传。维持 busy、防重复点击、卸载/导航请求失效和草稿变更后分享结果失效机制；只在服务端确认保存后展示可复制链接。上传超时可重试，同一快照仍得到相同链接，不引入额外幂等键或“发布中”状态。建议读写请求超时均为15秒，允许用户手动重试，不后台无限重试。

分享入口需有简短说明“生成链接会将案件保存到 LIE 服务端，持有链接的人可以查看完整内容”。这是从 fragment 转为云存储的实际边界变化，不新增作者表单或复杂发布流程；具体位置交 UI owner 评审。

读取完成后才加载案件，不自动申请麦克风、不自动建立语音连接；加载过期响应不能附到新路由。刷新会重新取案件但不会恢复局内状态；一局开始后使用内存中的快照，不随网络变化替换内容。

| 情况 | API/界面行为 |
| --- | --- |
| 非法 JSON/案件结构/标识 | `400`，明确内容或链接有误 |
| body 或规范化内容超限 | `413`，提示案件内容过大，草稿保留 |
| 错误 Content-Type/压缩 body | `415`，不尝试当文件或压缩包导入 |
| 跨域写入 | `403` |
| 内容不存在 | `404`，“案件不存在或已不可用”；不伪称一定过期 |
| 存储不可用 | `503`，提示稍后重试，保留草稿；不输出不存在的链接 |
| 前端网络断开/超时 | 明确网络失败并可手动重试，不显示“内容损坏” |

所有 API 错误用稳定 error code 对应前端文案，不透出内部异常或配置。首版不加 CDN/Worker Cache 层，API 返回 `Cache-Control:no-store`（包括404/错误）；避免缓存未命中和额外失效设计。未来有真实读取成本或延迟证据再考虑缓存。

### 留存、删除和内容责任

默认不设 TTL，不配置自动生命周期删除。无作者账号，也不凭“知道内容 hash”授予删除权限；首版不做用户删除/撤回 API、编辑覆盖、拥有者 token 或作品列表。首版无删除功能已随本次“此外没问题”的整体反馈获认可，并非长期有效自然推导出的权限选择。

运营方可通过受控的管理能力处置异常内容，不向前端开放管理接口；删除存储对象无法召回下载副本。仅删除对象也不能阻止相同内容再次上传；如需要可靠的禁止重新分享/投诉处置流程，须明确封禁记录和运营责任，不假装已有完整内容治理。内容 hash 可被对已知内容的猜测比对，不用于私密分享。

首版建议不另建备份/恢复系统，也不声称有独立备份。服务部署、代码回滚和 CI 清理不能删除存储桶或其中内容；本地开发缓存可丢弃的生命周期不能套用到生产桶。若需要可恢复误删的保证，需另定备份与恢复目标。

## 模块、验证与实施依赖

实施建议保持最小边界：game-core 的游戏规则不变；将 v1 规范化函数置于现有可共享纯 TypeScript 层（位置在实施 review 时确认，不为两个函数预建通用存储框架）；gateway 新增独立分享 handler 并在现有入口接线；web 更换分享生成函数及 `/play` 加载分支，保留旧解码器和本地草稿；配置新增 R2 binding 和本地代理。`/api/health` 当前固定报告 `storage:none`，需同步改为准确的绑定配置状态，不用 health 探针反复写入存储。

必要测试：

- 序列化字段排列、人物顺序、未知字段、可选字段、null、文本空白、UUID/内容修改的身份结果；固定 v1 样例 hash。
- UTF-8 多字节、等于/超过上限、无或虚假 Content-Length、分块超限、非法编码/JSON、压缩 body、缺少配置。
- Worker POST→GET→相同内容再POST得到相同ID；不同内容不同ID；不能通过客户端指定 key 覆盖；存储失败不返回成功；无用户删除/列举入口。
- 同源校验、绑定缺失与存储异常；不写限流、停写开关或读取体积限制的测试。
- web 分享失败保草稿、超时重试、busy/过期结果、路由切换、原生分享/复制沿既有能力；本地存储与生产完全隔离。
- 旧 fragment 正常/坏编码/超量、含新旧两种标识；新链接加载、404/503/超时、不支持版本；可变人数、试玩、重开与已有指认语义不变。
- 后续隔离在线环境验证刚写即读、重复分享、真实写入大小拒绝、与部署配置的实际匹配；不调用真实语音即可验证分享功能。
