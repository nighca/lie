## Findings

### RC-01 — P2 blocker: expired-and-removed artifacts stop later releases

`/Users/nighca/code/nighca/lie/scripts/release-assets.mjs:248` requires exactly one artifact match **before** line252 can inspect expiration. A previous successfully deployed/uploaded compatibility run whose archive has expired and disappeared from the API therefore produces `Deployed release artifact missing or ambiguous`, aborting Restore and preventing the next gateway build/deploy. This is especially likely after a quiet interval exceeding the candidate14-day artifact TTL while job/run history remains available. It defeats the documented policy of explicitly reporting/omitting expired selected generations. Current live production is not harmed by reviewing this unpublished candidate; the impact is future deployment availability.

This API case has primary-source support, not just speculation: GitHub's2026-09-24 changelog says expired artifacts no longer appear in run data or REST API results, whereas previously metadata remained visible despite the files already being deleted. Historical production information can still be found in run logs. [Official change](https://github.blog/changelog/2026-09-24-expired-github-actions-artifacts-no-longer-shown-in-ui-and-api/). Artifact retention can be shorter than workflow/run history because a per-artifact TTL is configured by the upload action.

[Offline probe RC-01](probes.mjs) invokes the actual previousReleases function with a successful deploy/upload job and an empty artifact list after expiration. It reproduces the thrown error before any download. Existing expiry tests return `expired:true` metadata and therefore miss this removed-metadata case. [Results](probe-results.jsonl).

Minimal correction direction: explicitly distinguish the supported retention window and expected expiry/removal from an unexpectedly missing in-window archive, using trustworthy deployment/upload timing and the chosen policy or preserved expiry metadata. Report omitted identity/reason rather than silently claiming bootstrap/full continuity. Do not simply treat every missing artifact as expired, silently weaken provenance checks, enable a budget gate or add deletion permissions. Choosing the actual TTL remains the pending user decision; handling its normal expiration is a separate correctness requirement.

### RC-02 — P2: truncated workflow history can silently choose an unproven latest pair

`release-assets.mjs:224` requests only the first100 workflow runs; line225 does not inspect `total_count`/pagination. It sorts completion times only inside that subset, and line263 accepts the search whenever at least two eligible candidates were found. That does not establish that no omitted run/attempt deployed more recently. The feature specifically supports earlier attempts and sorts by deployment completion time, so run-list position must not be treated as a proof of deployment order.

Probe RC-02 supplies a valid paginated response shape with total_count101: page1 has100 runs including two eligible deployments, while an omitted older run has a later successful deployment on rerun. The function never requests page2 and accepts the page1 pair. The probe asserts this incomplete-search acceptance; it does not claim a live API run ordering was measured or that every rerun is outside the first page. Even without relying on a particular undocumented API sort, the current search cannot prove the declared latest-by-deployment ordering when its evidence is incomplete. [GitHub workflow-run API pagination and run/attempt fields](https://docs.github.com/en/rest/actions/workflow-runs?apiVersion=2022-11-28).

Impact: a genuinely recent prior generation may be dropped, breaking old open clients despite an apparently successful restore report. Minimal correction: traverse additional pages within an explicit query budget, or fail/qualify the result when history beyond the evidence bound could affect selection. A count limit alone is acceptable if honestly surfaced as unknown, not a false latest-two claim. Don't continue unbounded API enumeration just to make the fixture pass.
