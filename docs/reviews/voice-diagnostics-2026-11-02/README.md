## 一次窗口的固定条件与最少数据

同一台选定设备、同一 Safari 页面/实际版本、前台、不锁屏、同一输出方式和正常音量，不在会话中切浏览器、网络、设备或音频设置。已有的网络描述可复用，只记录本轮是否不同；不收 IP、运营商账户、精确位置。两项症状各自可以出现或未出现，不要求同时复现。

| 项目 | 最少记录 | 缺失时 |
| --- | --- | --- |
| 环境 | iPad/iPhone、已知机型/系统、Safari已知版本、页面构建号、外放/耳机、是否一直前台；网络类别仅已有或用户愿意说明的粗粒度值 | 未知，不为补齐另开语音 |
| 主观现象 | 本人是否沉默、已否听到角色、首次/后续回答；自打断/错误玩家气泡、声音间断各为出现/未出现 | 不将“未复现”写成修复 |
| 网络事件 | 下行 `tts.start`、`tts.sentence_start`、`stt`、`tts.stop`/`is_aborted`、socket close；只事件类型、方向、时间 | 不抄文本或完整JSON |
| 音频消息 | 异常附近连续少量下行 binary 的时间及payload bytes；数量上限见步骤；注明完整/部分/未知、有否省略行 | UI不显示就写无法观察，不复制binary；transfer size或帧头大小不代替payload |
| 本地状态 | 既有 UI 可见的 context state / visibility 变化 | 默认无法观察；人工“始终前台”不冒充visibility事件 |
| 播放器 | 调度、queue、耗尽、本地stop原因 | 本路线无法观察，不依据网络缺少stop断言本地没stop |

时间统一保留 Inspector 显示值，以该回答首条下行 `tts.start` 为0，事后换算；未见start则以首条摘录为0并注明。不要混用Mac墙钟、设备时钟、provider时间或AudioContext.currentTime。用户听到的异常只能粗略定位，不能声称与某帧精确同步。binary时间表示检查器观测，不是扬声器出声，也不能直接测出跨境/CF/provider单段延迟。

## 拟交总协调的一份用户步骤

预计首次连接约3–5分钟，正常短对话约30–60秒、整理约2–3分钟；这些只是预估，不要求持续测试到复现。

1. iPhone/iPad用数据线连接Mac、解锁并处理信任提示。设备设置→App→Safari→高级→网页检查器打开；Mac Safari设置→高级→为网页开发者显示功能。打开正常LIE页面，Mac Safari开发→该设备→目标页面。已做过的不再重做。[官方启用说明](https://webkit.org/web-inspector/enabling-web-inspector/)
2. 开始语音前，在原有版本对话框看页面构建号（短号可手抄，无需操作系统剪贴板）；关闭对话框。检查器选择Network，过滤`/api/voice`；不启用断点/暂停、不改缓存或Feature Flags。没有版本入口就记未知，不为此切设备或强制刷新。
3. 用户自己发起一次正常短对话。问题照常问，无需特定台词；角色回答时保持沉默，正常使用外放，不改音量。出现任一异常时记住首次/后续回答，随后结束语音；如一小段对话无异常也结束，不自动重复。
4. 打开路径恰为`/api/voice`的WebSocket消息面板（不是`/status`或`/prepare`）。只摘录异常附近的事件类型、方向、时间、aborted布尔。若没有异常，可摘录一次回答的start/stop并记“未复现”，无需逐帧抄全部对话。
5. 如果消息面板能显示binary时间及明确的payload bytes，最多摘录异常处连续10条下行binary（尽可能前5/后5）及夹杂的上述事件；保留原顺序，标明此小段有无省略行。无法定位时选一次回答开头10条，并标明非异常对齐。不要为凑足帧数再开对话。逐帧复制负担大就先只给现象和事件，bytes/间隔写无法观察。不得把Inspector的“复制全部”或导出HAR作为简便替代。
6. 先正常结束游戏语音，再整理下方纯元数据文本发给总协调。这里只是手工摘录，不要求复制完整网络数据；可手抄，用户若自行复制也仅复制自己整理的白名单文本。Agent不读写系统剪贴板。关闭检查器即可，不清tab/storage、不改配对或停止其他服务。

```text
设备/已知系统和Safari版本：
页面构建号（可短号/未知）：
输出/本轮音量是否改变：
一直前台且未锁屏：是/否
网络类别（已有/可选）：
整场首次回答 / 后续回答 / 不确定：
角色回答时本人沉默：是/否
已听到角色出声：是/否
自打断/错误玩家气泡：出现/未出现
声音间断：出现/未出现（粗略在句首/句中/句尾）
摘录覆盖：连续无省略 / 有省略 / 不确定；时间单位及显示精度：

Inspector显示时间 | 收/发 | 类型 | bytes（binary才填） | aborted（stop才填）
……

未显示或无法观察：本地调度/本地stop/context事件/visibility事件/……
```

常规消息只收类型与必要布尔，绝不收正文、PCM、工具调用参数、完整JSON、请求头、Cookie/token、身份/会话ID、完整URL查询、HAR或录音。上行binary不作为首轮必填；若用户误发敏感内容，不将其写入仓库。

现有独立合成音诊断页仍是无provider页面，不用于这次真实游戏，不要求重测A/B/C。其一键复制已上线；本次Inspector没有现成的脱敏一键复制功能，不能假称已有，也不新增未经批准的脚本或追踪器。若手工成本或UI缺失使采集不可行，停止并向总协调报告缺口，再决定是否需要统一opt-in工具。

## 联合验收与判读表

| 同次观察 | 可以支持的判断 | 不能据此断言 |
| --- | --- | --- |
| 本人沉默，收到STT且随后自打断 | 存在上游识别事件与症状的关联；对齐aborted顺序 | 已确认声学回灌、AEC失败或具体浏览器缺陷；没有正文也不能证明STT与台词相同 |
| aborted先到 / 没有STT | 保留provider中止或未捕获事件的分支 | 客户端一定主动误打断 |
| 听到间断，附近没有网络tts.stop/close | 这段摘录未见网络终止，需结合binary节奏 | 本地没有stop，或已经证明buffer underrun |
| 同回答、连续无省略窗口内binary显示较长间隔或随后集中到达 | 列客户端可见交付节奏及精度，保留现有缓冲可能覆盖间隔的解释 | 缓冲一定耗尽，或一定由跨境网络/CF/provider某层造成；不设超过100ms必卡阈值 |
| 摘录窗口内binary节奏平稳，用户粗标同处听到间断 | 需排查本地调度/context/输出或PCM内容等缺口 | 整回答节奏平稳、网络绝对正常，或已排除provider生成停顿 |
| 页面前后台变化或锁屏 | 有生命周期变化的环境线索 | 已测到context挂起；不得将人工观察当精确事件 |
| 只复现一个症状 / 两项都未复现 | 分别记录，不机械补齐测试组 | 已修复另一症状，或用户测试无效 |

首轮数据若不足，只列出一个具体缺口及下一步可能区分的假设，交总协调审查；不得两边各自发补测。音频消息bytes若确为已确认PCM16/16k/mono的payload，时长可离线用`bytes / 32000`秒换算；不能用20ms上行帧规格假定每个下行消息也固定640bytes。截断或有省略时仅称“所列事件间隔”，不称真实流最大间隔；跨回答自然静默不计同回答供给缺口。正常tts.stop会flush/drain，不等于强制清空本地播放。
