# LIE 视觉方向提案

更新：2026-10-23。状态：待用户选择，尚未制作风格板、正式 Logo、界面或图片。

视觉负责人统筹 UI、Logo、人物与演示物料的一致性。已确认现代单人语音侦探、桌面 Web、首案三名嫌疑人、灵矽接入和多游戏内容驱动；具体案件、玩法与模块架构仍待确认。以下方向不预设案件发生在警局、办公室或某个行业，也不把界面草案当作玩法批准。

## 两个可选择的方向

| 设计要素 | A · 夜间调查台（推荐） | B · 公开案卷 |
| --- | --- | --- |
| 核心感受 | 玩家在安静的调查台前集中听人说话；深色环境托住人物和语音，浅色材料提供阅读区 | 玩家在整理一套现代调查档案；浅色纸面、清楚的编号与排版，突出材料之间的关系 |
| 色彩示意 | 背景 `#11171C`，面板 `#1B242C`，正文 `#EEF1ED`，次级文字 `#B7C1C7`；琥珀 `#E6B66A` 用于当前操作；材料底 `#F3EFE5` 配深色字 | 背景 `#F2EFE7`，面板 `#FFFCF5`，正文 `#222B31`，次级文字 `#59646B`；深蓝 `#24495C` 用于主操作，赭红 `#A33B30` 少量用于强调 |
| 层级与形状 | 细边框、适度圆角、少量阴影；以空间与明暗分组，避免满屏发光边框 | 直线分栏、近方角、编号与细分隔线；使用页边与留白分组，纹理只作轻量点缀 |
| 布局 | 对话占主区域，人物切换位于上方，案卷固定在侧栏；关键材料展开成宽阅读面，保留当前人物和语音控制 | 对话与案卷并列，材料用明确的标题、来源、正文和操作区；可读面积优先，长材料避免层层弹窗 |
| 人物表现 | 小幅裁切的统一单色插画肖像或轮廓；说话时边框与状态文字变化，不做口型或复杂表情动画 | 档案式头像、姓名与身份排版；头像采用相同画幅和处理方式，可用简单插画完成 |
| Logo 方向 | 几何字标 LIE，以一处断开的笔画或错位形成“证词有缺口”的含义；保持缩小后可读 | 字标 LIE 配一条校对式标记，呼应记录与更正；避免真实机构徽章或警务符号 |
| 跨案件与物料 | 核心底色、字体、组件保持一致；案件只更换封面、人物素材和内容。演示封面沿用深底、字标与一处材料剪影 | 核心纸面、编号和排版保持一致；案件更换封面、人物和材料。演示封面沿用案卷标题与编号构图 |
| 收益与代价 | 语音状态醒目，演示时容易形成记忆；要控制暗面密度和材料明暗切换，不能把长正文压成低对比小字 | 中文和长材料阅读直接，素材依赖低；需要更仔细的版式节奏，才能传达审讯张力，避免接近普通文档工具 |

**建议先选 A。** 它能给语音对峙留出舞台，同时用浅色材料保证证据可读性；人物仍可采用简单插画，不依赖写实人像生产。若用户更希望玩家持续读材料、做比对，B 更合适。两套先作为整体方向选择，不同时制作两套完整界面。以上 HEX 为示意，正式组件需要检查实际背景下的文字与交互对比度。

## 两个方向共同遵循的规则

**文字与中文阅读。** 首版先用系统字体栈：中文按设备使用苹方、微软雅黑等可用无衬线字体，英文用 `system-ui`；不因字体缺失阻塞页面。标题建议 28–32px / 600–700，分区标题 18–20px / 600，正文 16px / 400，辅助信息 14px / 400–500；中文正文行高约 1.7，长材料每行约 28–36 个汉字。时间戳和证据编号可用系统等宽字体，正文不使用仿打字机字体。正式字号以实际桌面布局和浏览器缩放验证；定制字体如有需要，另核实授权与加载成本。

**证据与证词。** 材料固定呈现标题、来源、时间和正文，关键事实依靠清楚的排版呈现，不用颜色暗示答案。证词标明发言人；更正采用“原说法 / 更正说法”并置或关联展示，保留历史。证据“已取得”“已向某人出示”和角色“正在说话”使用不同标签，不让视觉状态替玩家判断撒谎或归罪；若以后需要可信度等新机制，先回到玩法讨论。

**语音状态有稳定的位置。** 保留同一控制区和状态文字；动画只辅助说明，不遮挡证据或对话。

| 状态 | 玩家能看到和操作的反馈 |
| --- | --- |
| 就绪 / 麦克风未授权 | “可以提问”或“需要开启麦克风”，配明确按钮；未授权给出文字输入入口（若玩法批准） |
| 收音中 | “正在听你说话” + 麦克风图标 + 输入电平；控制按钮显示“结束说话” |
| 识别或等待回应 | “正在识别”或“等待回应” + 轻量进度动效；只在接口确实区分状态时分别显示，不编造阶段与倒计时 |
| 人物说话 | “某某正在说话” + 播放图标；提供明确的“打断”操作；音频动效不代表人物情绪 |
| 打断 / 切人 | 播放停止、状态回到明确的新阶段；新人物姓名与选中标记同步变化，旧回答不在新人物区继续滚动 |
| 断线 / 失败 | 简短原因、重试或恢复入口；区分未送达与已送达，保留玩家可见的历史，避免重复操作不确定性 |

**可及性与可测试性。** 所有状态同时有文字或图标，不能只靠颜色；选中人物兼用边框与文字标记。键盘焦点可见，按钮有可读名称，支持浏览器缩放和减少动态效果；语音记录支持静音阅读。避免闪烁、自动滚动打断玩家阅读、频繁播报实时音量。人物数量和证据数量由数据驱动，不能把三人布局做成不可扩展的背景图片。

## 确认方式与后续交付

可以先制作一份低成本风格板供用户确认：同一组虚构占位内容下，展示背景与文字、一个人物区域、一张证据卡、语音控制区和字标草图。**该风格板需另行制作，目前不存在；正式设计在用户批准整体风格后开展。** 若两种方向难以通过文字选择，可各做局部对照，无需先制作完整页面。风格确认允许先于案件选定；正式屏幕结构则需与获批玩法和架构同步。

下一步交付范围：

- 关键屏：接案、审讯主屏（含证据展开与各语音状态）、结案与反馈；先确认一张主屏再扩展。
- 组件与 tokens：颜色、字号、间距、边框、焦点、状态、人物卡、证据卡、对话项和主操作；提供文字长短及不同人物数量示例。
- 品牌与素材：正式字标、单色与小尺寸版本、浏览器图标；统一人物素材规范；演示封面与在线体验入口封面。
- 与前端交接：根据获批的公开 DTO 映射可见状态和交互，不让视觉组件读取秘密或自行推断游戏事实；明确素材槽位、裁切比例、替代文本、缺图处理及组件状态清单。具体 token 名与组件接口由视觉负责人和前端负责人共同冻结。

视觉方向本身不需要自动化测试；实现后由前端在 fake API 下验证关键屏、键盘操作、长中文、麦克风失败与切人状态，再用真实浏览器人工检查阅读和声音反馈。全套设计保持本地 review 后串行集成、里程碑 push；未获架构确认前不进入应用实现。
