用户已认可整体设计方向，并撤销本文初稿中的读取体积检查、IP限流和停写开关；要求单项写入上限高于128 KiB。用户另要求缩短原64字符哈希标识，当前整体设计已确认128 bits＋无填充Base64URL（22字符）。本文以下保留初次研究及当时建议以供追溯，**不作为当前实施规格**；修订规格以[整体设计](share-storage-design.md)为准。后续用户整体批准并授权推进，1 MiB写入上限与128 bits/22字符参数已确认；UI需先有交互Demo供审看。本地R2模拟是Cloudflare工具链提供的能力，不是项目自行实现模拟。

## 初次研究结论建议（含后来撤销项）

复用现有 Worker，为案件分享增加两个同源 HTTP 接口，绑定一个私有 R2 Standard 桶。以服务端生成的 SHA-256 内容标识作对象键，保存规范化 JSON。首版不加数据库、账号、列表接口、作者删除接口、公开发现、预签名上传或通用存储 SDK。

这改变了原本 Worker 仅作 provider transport 的职责，属于需要用户批准的架构扩展；不改变浏览器判案、会话与 provider 凭据边界。所有新增路径仅服务案件分享，语音访问策略保持原样。

已确认方向：默认不过期；不可变内容快照、修改生成新链接；统一序列化；不在读取时重新计算哈希。其余具体选型、接口、数值和策略均为本次建议。

## 平台比较与依据

| 选项 | 与当前需求的匹配 | 判断 |
| --- | --- | --- |
| R2 | 按 key 保存对象，Worker binding 可 get/put，支持条件写入；写后读全球强一致 | 推荐，适合分享成功后立即打开 |
| KV | 接口简单、读多写少，但最终一致，跨节点可延迟60秒以上，且未找到的结果也会缓存 | 不推荐首版，为立即分享引入等待/重试语义 |
| D1 | 可以用主键保存内容及唯一约束；SQL适合查询、管理和关系数据 | 可行，但当前只需按内容ID读写，不值得增加表与迁移；读复制还有会话一致性设计 |
| Durable Objects | 适合全局严格配额或需要协调状态 | 当前不需要，不因存快照或粗限流引入 |

来源：[R2一致性](https://developers.cloudflare.com/r2/reference/consistency/)、[R2 Worker API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[KV一致性](https://developers.cloudflare.com/kv/concepts/how-kv-works/)、[D1读复制](https://developers.cloudflare.com/d1/best-practices/read-replication/)。R2自己的强一致不等于另外加上的HTTP缓存会即时删除；首版避免额外CDN缓存层和缓存未找到结果。

## 内容协议与职责

建议内容标识为64位小写SHA-256十六进制字符，协议v1置于路由或标识外层。标识长于随机短码，但仍是固定约70字符，不需要碰撞表、截断长度决策或额外映射。示例路由 `/play?share=v1.<hash>`，沿用 `/play`，不让内容ID与案件自身 `game.id` 混用。

Worker对JSON执行 `validateGame`，按照冻结的v1字段投影输出确定顺序的JSON；UTF-8字节计算哈希，存为 `games/v1/<hash>.json`。不对gzip字节计算身份，也不引入通用canonical JSON库。当前 `validateGame` 已按固定次序重建字段并去掉未知字段；应显式冻结v1序列化契约，避免以后修改校验器时无意改变旧内容身份。

保存原始文本、数组顺序、案件ID和角色ID；不trim、不改变换行、不做Unicode规范化、不重编号。因此同一数据快照稳定，不承诺语义相同但UUID不同的两份案件去重。`summary`缺省与空字符串是否视为不同，建议按现有契约区分，避免凭空定义语义归并。格式v1是内部存储协议，不是作者作品版本管理。

哈希只由Worker计算；前端POST案件，收到标识再生成当前站点的链接。客户端不能任意指定对象键，不直接接触R2或账户凭据，不需要CORS桶配置或S3 SDK。读取后仍校验案件契约和预设形象ID，但不重算哈希。当前形象目录在web层，实施时需确定Worker共享的最小预设ID表，避免把图片资源导入后端；这不应改变core独立于呈现的边界。

## 最小接口提案

| 接口 | 输入/输出 | 行为 |
| --- | --- | --- |
| `POST /api/shared-games/v1` | `application/json`的GameDefinition；返回`{ id }` | 服务端校验、规范化、算hash，保存对象；已有同ID返回相同成功结果 |
| `GET /api/shared-games/v1/:id` | ID；返回规范化GameDefinition JSON | 严格检查ID格式，再按固定前缀读取，限制返回体积；无列表、任意key、修改、删除能力 |

首版直接put相同key与规范化字节即可：同hash对应同一内容，重复写入不改变内容语义，不需要HEAD预查或全局锁。R2支持条件put（例如 `If-None-Match: *`），但当前没有保存初次创建时间或禁止物理重写的需求，无需增加该分支。重复请求仍产生写操作，内容去重不代表操作免费。

POST仅接受同源浏览器请求；校验Origin与媒体类型、不开放CORS，拒绝不支持的压缩请求体。Origin只约束浏览器跨站调用，不能挡脚本伪造，不能当鉴权。GET同源使用，不公开bucket域名。首版返回 `Cache-Control: no-store`，不实现Range或CDN缓存，避免为节省尚未发生的读量添加缓存/下架一致性复杂度。

响应建议：400坏JSON/标识/案件契约、413体积超限、415媒体类型/编码不支持、429频率限制、404不存在、503存储不可用/新分享暂时关闭。错误体只含稳定code与安全提示，不返回原始内容或平台内部异常。成功POST用200，简化“已存在/新创建”区分；近似限流无法保证精确解封时刻，不要求构造精确倒计时。

## 体积及写入保护

建议输入原始UTF-8请求体与规范化存储内容均最多128 KiB，沿用现有解压内容预算。两处分别检查：Content-Length只能提前拒绝，仍需按流累计字节；读取对象先检查元数据size，前端下载也有128 KiB上限，防止错误数据无界读取。JSON在确定大小后解析。前端在分享前提示超限，服务器强制执行。该上限约束字节而非中文字符数，不自动增加每字段/人数硬限制。

匿名写入建议先采用：每来源IP约10次/60秒的近似限流、仅合法案件、单项上限，以及配置级“关闭新分享”开关。GET可以独立设置约120次/60秒的异常请求限流，避免正常接收人被写入限制牵连。确切阈值需用户确认并观察；共享网络可能误限，IP会变化，也不能挡分布式滥用。不能用客户端随机ID代替不可伪造的身份。

Cloudflare [Rate Limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)是每Cloudflare节点近似计数，并非全球严格累计预算；官方也指出IP可能被多人共享。此处IP是无账号前提下的折中，不宣称精确按人限流。建议不默认加入DO计数、Turnstile、账号或自动封禁系统。预留运营关闭POST而保留GET的能力；限流故障应拒绝新写入，不悄悄绕过保护。

这套简单保护**没有硬费用上限**。分布式请求、重复提交和未知ID读取仍消耗请求/操作；长期内容持续累积。首版以监测写入次数/对象量/错误和账户账单、人工关闭新增控制风险。若用户要求“绝不超过每月预算”，需要另外设计严格全局计数/预算停写，不能把近似限流或费用提醒说成硬上限。日志只记录状态、字节数及必要计数，不记录案件正文/答案/请求头secret，不另存原始IP日志。

## 本地开发与旧路径

默认本地模拟R2并持久化在当前worktree的忽略目录，不访问线上生产桶。现有gateway Vite已设置 `remoteBindings:false`；web开发代理目前只覆盖`/api/voice`，实现时增加分享API代理，不改服务端口/生命周期。不同worktree数据隔离；本机生成的localhost链接仅对应本机数据，不标成公开可分享。测试使用独立fixture，清理仅限自己的开发数据。

线上集成验证才显式使用独立开发桶/环境；不默认生产读写混用、不做自动回退、双写或同步。无需第一版就提供切换按钮；研发配置即可。R2与KV、D1均有本地模拟和远程bindings支持，Rate Limiting有本地模拟。[支持矩阵](https://developers.cloudflare.com/workers/local-development/bindings-per-env/)。当前cf beta绑定声明的具体写法与持久化目录仍需实施前核对项目锁定依赖；本WT未安装node_modules，本次未虚构可运行配置。

旧 `/play#game=...` 保留只读解码，继续有16,000字符与128 KiB解压限制；新分享仅生成存储链接，不给用户两种模式。离线创作/预览/本地草稿不受影响，在线分享失败明确提示重试，不静默回退长链接。旧链接无需批量迁移、后台上传或点击时自动转存；已有链接内容没有经过作者新的上传动作，不应因为浏览就自动持久化。

新链接与旧载荷同时出现时应拒绝为歧义链接，不猜优先级。案件加载侧可复用Application现有revision隔离；Editor分享上传侧则需补齐草稿变更、导航后的结果失效，当前仅有busy与mounted保护，不能误称已有完整上传revision机制。路由切换/离开时取消请求或忽略迟到结果，避免过时结果影响当前页面。新分享只在写入成功后展示可复制链接，失败不清草稿；短链加载只取案件，不启动麦克风/provider。

## 容易遗漏的产品边界

- 分享动作现在会把完整案件（含答案与各人物私有设定）上传至项目服务端；需在现有分享位置用一句短说明表达，不加独立发布流程。任何持链接的人仍能读取全文，hash不是隐私保护，也不是作者认证。
- 不提供作者删除/撤回或编辑覆盖。无身份时无法可靠判断谁是作者；删除权限token会引入新的保管/恢复体验。必要下架是运营操作，直接删除后同内容可被重新上传，因此若要求持续阻止需额外封禁记录，不能称首版已支持治理闭环。
- 默认不过期不等于永不丢失或永久可访问；不设置自动清理，不让发布回滚、开发环境清理或CI重建删除桶数据。首版是否需要独立备份/恢复目标属于运营取舍，不把R2的持久性误称独立备份。
- 内容快照固定不等于所有未来引擎/素材/AI回答固定；保证相同案件文本和配置，沿既有兼容策略，不把整套引擎版本打入每个分享包。
- 停写时保留读取；存储故障不影响官方案件与本地预览。新增存储健康状态不得暴露凭据，现有health中的`storage:none`应如实调整但不为探活每次读写R2。

## 验证与待确认

协议测试：字段顺序变化同ID；数组/文本/答案变化不同ID；重试/并发同内容不覆盖；旧v1规范化fixture固定；缺省summary、UUID与未知字段语义明确。

API测试：无/伪造Content-Length、chunked超限、128 KiB边界、非法编码/JSON/内容/预设ID、未知ID、R2故障、限流与停写、无任意key/列表/修改接口、错误不泄漏正文。用R2本地模拟作集成，不以fake证明真实Cloudflare强一致。

浏览器验收：生成→另会话打开→同引擎开局、修改新链接而旧链接不变、旧fragment正常/损坏/超量、离线分享失败保草稿、返回迟到与切路由隔离、本地重启保数据及worktree隔离。单独在获准开发环境核真实binding及写后立即读；不调用真实模型或语音来验存储。

建议整包确认的选择：现有Worker＋R2、128 KiB双边界、固定v1 SHA-256标识、匿名近似限流而无硬费用保证、默认本地模拟、旧链接只读兼容、新分享无长链回退、首版无作者撤回。实现与新资源/上线仍需独立授权；本提案不越过该边界。
