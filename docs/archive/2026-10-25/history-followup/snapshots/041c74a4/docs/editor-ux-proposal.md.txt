# 案件编辑器：分步创作与人物聚焦

状态：2026-10-24 交互原型，等待用户确认。仅调整创作体验；未改生产编辑器、游戏数据字段、引擎、分享编解码或语音服务。

## 这次解决什么

现版把所有内容放在一个长表单：作者要在多个完整人物设定和形象列表之间来回滚动，容易丢失当前创作对象；人物设定只有提示语，没有足够完整的写法示范。此次用三段可自由切换的创作空间取代长表单：

1. **故事设定**：标题、公共背景、共享询问时间。旁边实时显示玩家的接案信息，帮助作者区分公开背景与人物秘密。
2. **故事人物**：左侧人物卡片导航，只编辑当前人物。当前形象与编辑区并排，姓名、案件答案勾选、一个完整人物设定文本、换形象、删除分别有清楚的位置。全案用单个`culpritId`表示答案，选中当前人物会替换原答案，可取消至未选的写作状态。大屏卡片纵向排列，窄屏横向滚动。选中仅改变边框/背景，头像尺寸及卡片高度不变。
3. **真相结局**：只读显示人物步骤中已选答案的头像与姓名，再写完整经过；旁边预览正确指认后的揭晓。结局页不提供第二套答案选择入口，未选时提示返回人物编辑。沿用错误指认即终局、不揭晓的现有规则。

步骤是导航，不是门禁。作者可以先写真相、再补人物，也可随时回改背景；点击下一步不触发必填拦截，不为切换步骤增加确认弹窗。未完成内容只在试玩或分享时统一检查。

## 人物设定怎么写

实际引擎契约见 `packages/game-core/src/context.ts`：提示词先写「你正在扮演{name}」，再追加公共背景和「你的角色设定：」及原始 `profile` 文本。因此建议**第二人称「你叫……」**，是写给角色的扮演资料，不是要求作者写第一人称自白；这是一种清晰写法，不是内容校验的强制人称规则。

人物编辑区保留一句有价值的指导：「推荐用第二人称『你叫……』，写清亲历、所知和回答方式。」“看完整示例”打开可关闭的示例层，给出身份/口吻、明确事件与时间、知道与不知道的边界、被追问时如何回答的一整段真实示例。示例仍是一份纯文本，不拆成身份、秘密、规则等新增字段；不自动覆盖作者设定。

原型使用《谢幕前的小鸭》假数据，内含三个完整角色，方便评审比较。**预填示例只是原型展示状态**，不表示正式版要用示例覆盖现有草稿或默认给所有作者创建这个案件。

## 细节动线

| 行为 | 预期 |
| --- | --- |
| 切步骤、切人物 | 已写内容立即保留；页面不要求按顺序完成 |
| 加人物 | 添加空姓名/设定的人物，默认选中一个有效预置形象，焦点落在姓名；其他人物保留 |
| 删除当前人物 | 先局部确认，删除后选相邻人物；最后一人删完显示添加空态 |
| 删除正确人物 | 答案清空，不自动替作者另选；提示在人物编辑中重新选择 |
| 勾选案件答案 | 在人物编辑区勾选「将此人物设为案件答案」；选B替换A，取消可暂未选；试玩/分享前必须选定一位 |
| 换形象 | 选择层只提供有效预置形象，选中后回到当前人物，文本不变；取消「不使用形象」 |
| 恢复旧形象值 | null或失效ID不丢弃姓名/设定；试玩/分享时定位该人物要求选择有效预置形象，不暗中替换 |
| 从任一步试玩/分享 | 检查全案；有问题直接到首个对应步骤、人物、字段，并保留可点击的问题清单；修改后清单更新 |
| 重新打开/刷新原型 | 恢复独立原型草稿及上次步骤/人物；正式落地继续保留现有浏览器草稿契约 |
| 试玩离开 | 正式实现仍进入现有引擎，正在调查时才按游戏既有离开确认；创作步骤切换本身不是离开调查 |

原型把询问时间以分钟呈现，常用 5/8/10 分钟加自定义；游戏数据仍保留 `interrogationLimitSeconds`，不是修改计时规则。步骤标记只表达创作完整度，不引入游戏评分。

## 原型位置与运行

源文件：`design/editor-ux/index.html`、`style.css`、`prototype.js`、`model.js`、`appearances.js`。从仓库根运行 `python3 -m http.server 5343 --bind 127.0.0.1` 后，访问 `http://127.0.0.1:5343/design/editor-ux/index.html`。

所有人物、logo 从既有静态目录引用，没有生成新视觉形象。没有外部服务、麦克风、真实试玩会话或实际分享链接。试玩/分享弹层明确标记原型演示；不能把其操作当成真实引擎或语音验收。草稿只写 `lie-editor-ux-prototype`，不读写生产 `lie-editor-draft`。

## 本轮用户补充：形象必选、答案归入人物

用户要求已在同一原型上调整，仍未修改生产编辑器：

- 每个人物试玩/分享前必须引用当前有效的预置形象。新人物默认有一个预置选中；恢复草稿中的null或失效ID保留原文，不丢草稿、不无提示代选。校验问题定位到具体人物的「选择形象」按钮。编辑器的创作约束不下沉到core schema；引擎现有null/无效形象容错独立保留。
- 人物姓名下方用勾选项「将此人物设为案件答案」，说明「玩家最终指认此人物，即挑战成功」。视觉是勾选，数据仍只有一个`ending.culpritId`；B替换A，允许取消至暂未选，删除当前答案会清空。
- 结局步骤只读显示已选人物的头像/姓名。暂未选时可以先写完整经过，另有返回人物编辑的提示；不在结局页再次选择答案。试玩/分享的未选校验直接回人物勾选项，步骤仍自由跳转。
