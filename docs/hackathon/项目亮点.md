# LIE Hackathon 项目亮点讨论初稿

当前正式体验入口：[LIE](https://lie.agency/) · [创作案件](https://lie.agency/editor)，由用户启用并指向现有正式Worker；[最新发布核验](../releases/2026-10-25-main-refresh.md)已记录48316544。下文研究基线与当时最后确认版本是历史口径，保留原证据，不因域名更新将Draft改为用户批准。

LIE 是一款浏览器中的 AI 语音推理游戏。玩家与多名各有经历和隐瞒的角色自由交谈、追问和交叉核对，在共享询问时间内作出最终指认。项目已经具备三款官方案件、可复用人物形象，以及从创作、同引擎试玩到链接分享的完整应用路径。

最值得呈现的价值是：**让 AI 承担需要自由表达的角色对话，让程序承担必须稳定的游戏规则，再让普通作者通过文本扩展内容。** AI 同时参与了产品内的角色互动和产品外的工程、设计、验证工作；两者的证据应分别评价。

## 一 商业价值与产品设计

LIE 的产品设计围绕三个相互支撑的目标展开：让自由语音成为可推理的游戏，让角色和交互具有完整的体验品质，让玩家也能持续创造新内容。

### 把自由对话设计成有目标的推理游戏

LIE 把推理的主要操作放在“问什么、先问谁、怎样核对说法”上。人物交流只有语音，转写供只读回顾；最终通过按钮选择责任人，不要求撰写推理长文。角色可以隐瞒，玩家也可以改变问法或打断回答，这给固定谜底提供了不同的探查路径。

自由语音让玩家自己决定追问方向，日常小事件和有限询问时间则将体验收束为一局可完成的推理游戏。[玩法与视觉依据](../architecture.md)、[中文项目介绍](../../README.zh-CN.md)。

三个官方案件已作为内容包实现：

| 案件 | 人物数 | 共享询问额度 | 推理关注点 |
| --- | ---: | ---: | --- |
| 空盒里的纪念章 | 3 | 8 分钟 | 核对交接、保管与进出窗口 |
| 压轴怎么是鸭叫 | 4 | 10 分钟 | 核对播放内容、操作与独处时间 |
| 盐和糖的小乌龙 | 4 | 9 分钟 | 对照原配方、传话和实际分工 |

人数、额度来自[正式目录](../../content/case-catalog.json)。连接准备不占询问额度，启用后的静音、等待和回答都计时；切人保留剩余额度。耗尽后仍可回看并指认。错误指认终局失败且不揭晓，正确才展示完整经过。这样的规则给自由谈话保留目标、节奏和结束条件。[确定性规则](../../packages/game-core/src/session.ts)。

官方内容为这套玩法提供了三种不同的推理结构：物品交接、操作窗口和传话偏差，让玩家用不同方式核对信息。

案件设计明确每个人知道什么、没见过什么、隐瞒什么；关键结论应能通过多人的亲历交叉核对，不依赖责任人认罪或结局突然补充事实。第二、第三案分别保留了两条作者推演问序、误导排除和知识边界检查；最新修订又缩短了开场说明，将适合通过询问获得的细节留给玩家探索。这些具体工作支撑“认真设计过的推理内容”，真实模型与盲测效果则按第三节的验证范围判断。[第二案设计检查](../second-case-validation.md)、[第三案设计检查](../third-case-validation.md)、[最新内容修订](../case-content-revision-2026-10-25/README.md)。

### 用角色表现和交互细节建立完整体验

品牌名称 **LIE** 只有三个字母，简洁易记，含义直接呼应游戏中的隐瞒、追问与判断。名称与正式字标共同构成清晰的识别入口，也为未来围绕“谎言与信任”扩展产品内涵留出空间。[正式品牌素材](../../design/brand/README.md)。

LIE 以阳光黄、钴蓝、深蓝描边和暖白阅读面建立鲜明的卡通风格，品牌字标、人物、按钮、卡片与弹窗沿用统一的视觉语言。首页、审讯、结果页和编辑器共同使用设计规范、样式变量与公共组件，使产品呈现具有整体感，而不只是单个页面的装饰。[批准的视觉方向](../visual-direction.md)、[设计规范](../../design/ui/spec.md)、[公共组件](../../packages/ui/src/components)。

**人物的多状态形象、动画和声音是重点体验投入。** 八套预置形象都具有默认、聆听、等待和说话状态，并配有动画与声音配置。角色在玩家开口、等待回答和发声时呈现相应姿态，使语音过程有可见的陪伴和反馈；作者选用形象时，也直接复用这套表现能力。人物的视觉表现与语音过程共同构成角色感，是产品体验的重要组成。[正式形象资源](../../design/character-presets/manifest.json)、[动画制作流程](../animation/production-workflow.md)、[组合验收](../animation/combined-final-animation-verification-2026-10-25.md)。声音按形象配置，存在复用；动画嘴部不宣称真实口型同步。

语音准备期间显示醒目的连接提示和取消入口，直到传输、播放和麦克风真正准备完成才提示可以说话，准备时间不扣询问额度。正在对话时切换人物会接续到新人物，保留各人历史和共享时间；已经停止对话后切人则保持停止。错误退出准备状态并允许手动恢复，不以无限自动重试制造不确定等待。[对话交互实现与验收](../voice-connection-interaction.md)。

只读转写帮助玩家回顾说法，角色状态、按钮文字和可用操作共同说明当前正在发生什么；无输入时不伪造收音波形。人物动画与这些真实对话状态相连，让功能反馈和视觉表现保持一致。[界面反馈原则](../visual-direction.md#实现边界)。

LIE 采用浏览器访问与响应式布局，桌面和窄屏都能进入案件、切换人物、查看转写、指认，以及编辑和分享案件。窄屏会调整人物导航、操作区和弹窗布局；已有实际 391 CSS 像素浏览器检查覆盖编辑器、草稿、改编和连接提示等流程，包括可操作性与横向溢出检查。用户因此可以在不同尺寸的设备上访问同一套产品，无需安装专门客户端。[编辑器适配验收](../game-editor-implementation.md)、[改编窄屏验收](../remix-game-proposal/implementation.md)、[对话状态窄屏验收](../voice-connection-interaction.md)。

已实现的移动端布局与操作适配是产品亮点；真实手机上的麦克风、播放、外放回声及不同移动浏览器兼容性仍需补齐，当前不把窄屏桌面浏览器检查表述为全部移动设备的完整语音验收。

### 让玩家从体验者成为创作者

LIE 把案件创作能力交给玩家，内容可以由用户自由扩展，不再局限于平台预置的三个游戏。平台承担人物美术、动画、声音和运行引擎的制作与接入，作者主要关注故事本身：不需要编程、绘制人物或搭建语音服务。简单的游戏规格、可直接选用的预设形象和友好的编辑器共同降低创作门槛。

编辑器已实现故事、角色、结局三步自由往返：作者填写公共背景和每人的纯文本设定，选择预设形象、唯一答案及询问时长。未完成内容保存在当前浏览器，试玩直接使用正式游戏引擎。完成后，完整案件压缩进 URL fragment，接收者打开链接即可加载，无需为故事建立账号或数据库。[编辑器实现及验收](../game-editor-implementation.md)、[分享编码](../../apps/web/src/editor/share.ts)。

结果页还可将当前官方、分享或试玩案件复制成新案件继续改编；只复制静态内容，不复制转写或消耗时间。已有草稿须明确确认替换，失败保留原内容。这使“玩到一个想改的故事，再创作并分享”成为已实现的产品闭环。[改编机制与离线浏览器验收](../remix-game-proposal/implementation.md)、[最终入口组合验收](../remix-game-proposal/quiet-combined-verification.md)。

由此，人物美术、动画和声音的投入不仅服务于官方三案，也成为每位作者可以直接使用的创作资源。不同人数的案件共用同一引擎，内容增长无需逐案开发游戏逻辑。案件与角色资源还具有统一规格，使这种复用有机会进一步扩展到更多制作工具和内容消费场景，技术基础见第二节。

链接分享服务于朋友之间的直接游玩，“投稿给官方”则让用户作品有机会进入官方内容库。编辑器校验案件、展示并复制规范 JSON，再引导作者到 GitHub 创建文件并提交 Pull Request，由维护者评审后决定是否收录。这个设计复用了 GitHub 的版本记录、差异比较、讨论与审核机制，同时省去自建投稿后台和审核系统。LIE 无需索取作者的 GitHub token，提交由作者在 GitHub 上确认。[投稿入口实现](../../apps/web/src/editor/submission.ts)、[编辑器实际验收](../game-editor-implementation.md)。

已实现的是投稿材料准备和 GitHub 页面引导，并非一键自动创建 PR。研究基线的仓库仍为私有，外部用户完整投稿须待仓库实际公开；尚无外部投稿成功记录。该开放前提不影响这一产品机制的设计价值。[投稿方案与开放前提](../editor-official-submission-proposal.md)。

### 品牌与内容的延展潜力

**未来玩法设想：** LIE 的含义不限于当前由玩家识别 AI 角色隐瞒的审讯玩法。用户于 2026-10-25 提出，未来也可探索由玩家撒谎、AI Agent 追问并尝试识别的角色反转。这样的方向延续同一品牌主题，同时改变人与 AI 的博弈关系，体现名称的内涵延展性。该方向尚未设计或实现，具体规则与 AI 判断效果留待后续探索。

现阶段可提出的商业假设是：官方案件吸引初次体验，创作和分享带来内容扩展；未来可讨论精品案件包或面向活动的主题定制，但这些属于设想，未决定收费、分成或客户方向。

当前没有可支持用户规模、收入、留存、付费意愿或获客成本的统计。下一步最有价值的是观察陌生玩家能否独立完成首局、是否愿意再玩，以及作者能否完成并成功分享一个可玩的案件，同时测量每次有效游玩的实际语音成本。浏览器计时不等于供应商费用硬上限；正式访问控制、并发资源分配和成本控制仍未闭环。[公开语音边界](../online-voice-preview.md)。

## 二 架构设计

### 浏览器规则与薄网关各有职责

Vue 和 TypeScript 构成前端；独立 TypeScript 核心负责内容校验、会话、逐人历史、询问额度和指认。浏览器编排器处理连接、音频和异步事件，薄 Cloudflare Worker 保管供应商连接凭据并转发协议。Worker 不承载案件规则或局进度，也没有自有游戏数据库。[已批准架构](../architecture.md)、[核心源码](../../packages/game-core/src/session.ts)、[网关源码](../../apps/gateway/src/index.ts)。

该边界将固定规则与随机对话分开：AI 可以自由作答，但不会改变答案或裁决胜负。切人、重开和结束时，编排器通过会话、人物与连接代次约束迟到事件，避免旧回包写入当前人物；有关行为由 fake provider 的延迟、乱序和失败测试覆盖。[编排器](../../apps/web/src/application/controller.ts)、[测试目录](../../apps/web/test)。这些检查证明本地状态处理，不证明供应商多用户隔离。

**低基础设施成本与低运维负担：** 游戏计算和会话状态由玩家浏览器承担，内容随静态资源分发，自有后端只需薄 Worker 转发语音协议。相比需要常驻游戏服务器和数据库的方案，项目省去了相应的服务器维护、数据库备份及会话存储管理，降低了启动和持续运营的基础设施负担。无共享游戏状态也减少了服务端扩容时的状态协调工作，为随访问量增长提供了更简单的基础。实际总成本仍包含语音 AI 调用，并发上限还受供应商配额与连接限制影响，需单独测量。

**明确取舍：** 完整故事与答案可在浏览器开发者工具中查看，当前不做防作弊保密；供应商管理凭据保持私密。项目接受这一内容可见性取舍，以换取更轻的部署和运维。

### 统一规格连接内容生产与运行消费

案件只保留机器必需的标识、人物、额度和结局等结构，故事背景与人物设定使用纯文本，不要求作者学习规则 DSL。人物通过 `appearanceId` 引用独立形象资源，同一形象可扮演不同案件身份。当前正式库有八套形象，具备状态图、配置音色与动画资源；这不意味着八种完全不同声音或真实口型同步。[作者规格](../../content/games/README.md)、[形象清单](../../design/character-presets/manifest.json)。

内容与素材都有明确的规格，并由生产和消费两端共同遵循。文档、类型和校验器共同落实这些规格：

| 规格层 | 生产与校验 | 运行消费 |
| --- | --- | --- |
| 游戏包 | 作者或编辑器输出统一 `GameDefinition`，试玩、分享读取与正式加载均经核心校验 | 同一游戏引擎读取人物、额度和结局，不为每个案件编写专用逻辑 |
| 人物形象 | 权威清单定义稳定 ID、状态图、主题与声音；生成器核对路径、尺寸并输出运行资源 | 编辑器和游戏读取清单，案件通过 `appearanceId` 复用形象 |
| 动画包 | 部件、节点、轨道与状态遵循版本化数据契约；资源生成器使用统一解析器检查包和引用 | 独立动画播放器按同一契约解析与播放，不依赖具体案件、角色 ID 或 Vue |

依据：[游戏包类型与校验](../../packages/game-core/src/content.ts)、[形象规格与生成流程](../../design/character-presets/README.md)、[资源生成器](../../scripts/character-presets.mjs)、[动画包契约](../animation/contract.md)、[独立播放器](../../packages/character-animation/README.md)。

这一设计为更开放的生产和消费社区打下基础：未来创作者可以围绕相同规格制作案件或人物资源，工具作者可以开发辅助编辑、生成与检查工具，其他运行环境也可以据此实现内容消费。内容、制作工具与播放器因规格而衔接，生产方与消费方不必始终由同一团队包办。这里描述的是已有技术基础的生态潜力，尚不代表第三方工具、素材市场或外部消费社区已经建立；当前编辑器仍使用平台预置形象，不支持用户上传素材。

同一玩法下新增案件只需内容与必要呈现配置。引擎不写死三名嫌疑人，已有不同人数的正式内容和自动化验证。官方三案由构建期自动纳入应用，打开介绍不再额外请求案件 JSON；这是用入口 JS gzip 增加 **12,824 字节**换取减少案件加载依赖的实际取舍，图片和语音仍需加载。[多人数测试](../../packages/game-core/test/variable-character-count.test.ts)、[打包与真实浏览器证据](../bundled-case-catalog.md)。

### 自研轻量骨骼动画规格与播放器

为让生成的人物素材能够在游戏中持续表现，项目自研了一套轻量 2D 骨骼动画包规格及对应播放器。其基本方式是将位图部件绑定到具有父子关系的节点，通过枢轴、平移、旋转、缩放和显隐关键帧描述动作，再用 Canvas 2D 绘制。一个包内的多个动作共用部件，并将默认、聆听、等待和说话状态映射到相应动画片段。[类型定义](../../packages/character-animation/src/types.ts)、[包规格](../animation/contract.md)。

播放器负责确定性关键帧采样、循环、状态切换与过渡，渲染器负责层级变换、绘制顺序、裁切和遮罩。核心实现独立于 Vue、案件和语音供应商，Vue 组件只承担应用接入与生命周期管理；不同人物通过动画数据复用同一播放器。这里的“轻量”指围绕当前部件动画需求限定实现范围，使用浏览器原生 Canvas 2D，不包含网格蒙皮、逆向运动学等复杂能力。[播放实现](../../packages/character-animation/src/playback.ts)、[渲染实现](../../packages/character-animation/src/canvas.ts)、[运行时说明](../../packages/character-animation/README.md)。

这项自研能力把人物素材制作与产品中的动态表现连接起来，也让动画规格成为可复用的技术资产。包解析器与加载器校验版本、节点引用、部件尺寸和资源预算；异常、减少动态效果或资源不可用时由界面回退到静态形象。实际八套人物动画的接入和组合检查见[最终验收](../animation/combined-final-animation-verification-2026-10-25.md)。

### 对语音连接与分享输入设定边界

网关固定上游、检查来源，不提供任意代理；设有握手超时、单连接三分钟和 64 KiB 帧限制。浏览器分享另设完整链接 16,000 字符和解压后 128 KiB 上限，损坏输入显示错误。链接上限仍是暂定产品预算，跨浏览器和外部传输边界未完整验证，不承诺任意平台稳定分享。[网关](../../apps/gateway/src/index.ts)、[编辑器限制](../game-editor-implementation.md)。

### 面向线上交付的系统性性能优化

**建设目标：按工业级交付要求推进线上性能工程。** 用户于 2026-10-25 补充，主协调仍在安排相关工作；这里先纳入架构亮点，专项完成状态与线上效果待正式交付后更新。已有工作覆盖网络瓶颈测量、案件加载依赖、资源缓存、动画首帧和实际构建产物验证，体现从用户访问路径到交付链路的系统性优化。[线上网络基线](../performance/2026-10-25/README.md)、[组合验收](../performance/2026-10-25/combined-visual-verification.md)、[动画首帧验收](../performance/2026-10-25/combined-first-render-verification.md)。

工程价值在于让大量人物图片与动画的表现投入有相应的交付保障：减少案件加载的串行依赖，稳定资源利用缓存，资源更新通过内容哈希传播，构建检查防止缺图、坏部件路径或错误缓存响应进入交付产物。性能改动结合网络记录、资源字节身份和实际 Worker 产物验证，使优化结果可复核。

静态资源构建为内容哈希 URL，对成功的哈希资源使用长期缓存，缺失资源不会被 SPA 的 HTML 回退误作可长期缓存的图片。动画摘要覆盖完整包和部件，构建严格核对原始资源与实际产物。本地实际 Worker 产物浏览器样本中，暖刷新时 13 项不可变资源的网络传输字节为零；它是有界本地样本，未证明线上 LCP 或真实用户平均加载时间改善。[实现与测量](../performance/2026-10-25/implementation.md)。

## 三 AI 价值呈现

### AI 位于玩法核心

AI 承担按角色经历理解问题、组织回答、应对追问与隐瞒的工作。玩家能自由改变表达方式，因此互动不依赖预先列出的问答选项。持续语音已接入：一次开启后可多轮交谈和打断，切人时关闭旧连接；语音生命周期也驱动聆听、等待和说话的视觉状态。[持续语音方案及批准记录](../architecture.md#已批准的持续对话与询问额度)。

### 每个角色只取得自己的资料

当前上下文由公共背景、当前人物设定和本人历史组成，不包含其他人的私有设定或结局。端侧 MCP 工具按当前连接绑定的角色读取，模型不能靠自报人物 ID 获取另一人的资料。玩家转述他人说法仍是玩家输入，不自动成为角色亲历事实。[上下文源码](../../packages/game-core/src/context.ts)、[真实语音适配](../../apps/web/src/application/liveVoice.ts)。

这是可核查的输入控制，不是模型永不编造的保证。真实模型仍可能越界、出戏或过早认罪；确定性答案和语义评估承担不同职责。

### 真实效果已有局部证据和明确失败

| 证据层级 | 已有结果 | 结论边界 |
| --- | --- | --- |
| 自动化与替身 | 内容、状态、上下文、异步归属、协议及关键 UI 流程已有测试 | 不证明真人麦克风、听感或角色可信度 |
| 真实协议实验 | 合成 PCM 经真实服务完成多轮、打断和恢复；记录四次识别、上下文调用与 TTS | 非真人输入；不代表浏览器听到首音或即时停声 |
| 真人体验 | 用户已确认独立实验多轮与打断体验可用，并批准接入主应用 | 用户确认的有限体验，不是三案全量盲测或多设备报告 |
| 角色行为实测 | 已保存真实回答，包含知识边界检查、正常追问及攻击性问法 | 也记录了出戏和身份误用，问题仍未全部解决 |

首案真实模型测试曾发现关键时间事实错误；澄清人物设定后，限定回归的两道时间问题通过。后两案也曾完成预先固定的 12 答人工语义判定且全部通过；此前 6 答批次存在一项不确定结果，未混入通过率。这些检查使用文本触发真实模型、工具与语音输出，不包含真人识别或听音验收，且只适用于各自保存的内容版本。[首案问答及回归](../case-behavior-validation.md)、[后两案固定批次](../case-live-followup.md)。

证据：[协议原始记录](../realtime-voice-validation.md)、[真人反馈记录](../validation.md)及[接入边界](../architecture.md#已批准的持续对话与询问额度)、[角色行为](../case-behavior-validation.md)、[沉浸失败与停止记录](../role-immersion-investigation.md)。

最新三案背景精简及贺宁口径修订已经进入本地基线，但尚未做真实模型回归，不能说“问两句就承认”已经实测修复。[修订、替代方案与待测矩阵](../case-content-revision-2026-10-25/README.md)。玩家转写当前仍有 final-only 回退，不称实时 ASR；角色嘴部是合成动画，不称真实口型同步。

评审现场可通过一次正常追问、一次切人核对和最终指认观察 AI 对体验的作用。真人语音、外放和长会话的演示质量须在获准的实际环境预检；离线替身仅适合演示界面流程，须明确标识。

## 四 AI 工程效率

LIE 的 AI 工程实践贯穿产品设计、开发、素材制作、验证与交付。项目持续改进 Agent 的分工、上下文传递和审查方式，并把有效机制写入仓库，使一次任务中积累的经验能够被后续任务和接任 Agent 复用。

### 在项目推进中持续改进协作机制

协作方式随着实际问题演进。例如，跨专项零散消息增加协调负担后，规则改为以完整审查交付为单位批量汇报；主协调被实施和验收占用后，明确将非平凡任务连同配置、排障和验收整体委派，由协调者集中负责决策、实际审查与集成。相关演进可从 `AGENTS.md` 的提交记录核查，包括 `eeb7fec`、`d791f7f` 和 `b03c9d3`。[现行协作机制](../../AGENTS.md)。

开发服务的管理也由具体问题推动：项目整理闲置预览服务后，将端口、进程、来源版本、消费者及停止条件纳入服务台账，并明确服务复用和收尾责任。这类机制将临时处理经验变成后续 Agent 可执行的规范，减少资源冲突和重复环境准备。[实际清理与规则落地记录](../history/2026-10-25/development-service-cleanup.md)、[开发与服务台账](../development.md)。

文档同时承担协作中的记忆与状态传递：当前计划记录有效决定、优先级和下一步，交接记录保留所有权、依赖、提交及验证边界，历史与归档保存已完成、未采用和被替代方案。后续 Agent 能从仓库恢复工作依据，减少重新解释背景、重复调查和遗漏决定的成本；用户的新反馈也能继续修正规则。[当前计划](../project-plan.md)、[交接入口](../coordinator-handoff.md)、[归档规范](../archive/README.md)。

这套“发现协作问题、调整工作方式、文档固化、后续复用”的循环，是项目提升 AI 工程效率的重要方法。它的价值体现在可执行、可交接的组织能力，具体净节省的人时与费用仍需另行统计。

### 模块分工使独立交付成为可能

项目按内容与规则、上下文、浏览器编排、语音适配、公共 UI 和视觉资源拆分职责。开发代理使用独立分支和 worktree，交付基线、依赖、有序提交和验证记录；主协调检查实际完整 diff，再由唯一 integrator 在临时候选中按序集成，相关验证通过后快进本地 main。发布作为单独步骤处理。[协作规则](../../AGENTS.md)、[架构与独立测试计划](../architecture.md#模块拆解与独立测试)、[实际交付和集成状态](../coordinator-handoff.md)。

**效率体现：** 契约和替身使下游能在真实服务未完成时推进；专门代理能同时处理内容、界面、协议或素材等不同任务；实际审查与串行集成控制组合风险。这里可证明工作方式与交付结果，不能据此推算比人工快多少倍。

### AI 生成资源进入同一条可审查流水线

人物动画制作保留原图、生成提示、采用情况、部件和来源哈希；装配使用通用动画契约，逐人检查姿态、接缝、状态切换和静态回退。生成并非最后一步，用户视觉反馈、制作自验和独立技术审查继续决定是否接入。[制作流程](../animation/production-workflow.md)、[最终动画组合报告](../animation/combined-final-animation-verification-2026-10-25.md)。

报告记录的冻结组合通过 Web **281 项**、UI **43 项**和动画运行时 **33 项**测试，以及相应类型、构建和资源检查；八个动画包的 46 个相对部件路径均解析存在。这些数值属于对应候选的历史检查，未在本稿重跑，也不代表视觉和真人语音全覆盖。覆盖率同样保留采样提交、分母和 Vue 映射边界，不把历史徽章当现版本全量保证。[覆盖率口径](../coverage/README.md)。

### 调查结果也可以支持不实施

性能专项从网络瀑布定位静态资源重复校验，再完成哈希缓存与实际产物检查；另一项无损 PNG 研究对 81 张图测得节省 **5.28%**、压缩耗时 **66.73 秒**，当前决定暂不接生产构建。这说明工程判断会结合收益和成本，而不是把所有优化候选都上线。[网络基线](../performance/2026-10-25/README.md)、[PNG 研究](../performance/2026-10-25/png-lossless/README.md)。

角色沉浸实验也在第二问语义失败后停止，没有继续消耗剩余试验次数来寻找一次好回答。失败与未采用方案保存在仓库，供后续判断复用。[实际失败记录](../role-immersion-investigation.md#已授权候选实测第二问失败后停止)、[归档规范](../archive/README.md)。

### 人类决策与协作成本同样可见

用户决定了玩法删减、模块架构、视觉方向、持续语音体验，以及是否采用成本更高的方案。代理围绕这些决定执行、验证并反馈；遇到未授权的 provider、发布或产品变化仍需确认。

多代理也带来了共享文件协调、依赖排序、浏览器与端口占用、素材返工和重复验收风险。项目用文件所有权、服务台账、批量 handoff 和单 integrator 约束这些成本。当前没有完整的人时、token、费用或对照开发数据，因此适合陈述“交付范围与可核查过程”，不应声称净节省成本或量化效率提升。
