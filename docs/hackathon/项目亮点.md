# LIE Hackathon 项目亮点

讨论稿

[立即体验](https://lie.agency/) · [创作案件](https://lie.agency/editor)

**开口询问，听出破绽。** LIE 是一款浏览器中的 AI 语音推理游戏：与各有经历和隐瞒的角色自由交谈，追问细节、核对说法，在有限时间内找出责任人。

LIE 将 AI 的自由表达、可推理的案件设计和鲜明的视听体验结合起来，并把创作工具交给玩家。它既是一款可以直接游玩的游戏，也具备由用户持续扩展内容的基础。

## 一 商业价值与产品设计

### 自由交谈与精心设计的推理相结合

玩家决定问什么、先问谁，以及何时打断或继续追问。语音是与角色交流的唯一方式，只读转写帮助回顾，最终通过按钮完成指认。有限的共享询问时间让自由谈话具有节奏与目标；正确指认揭晓完整经过，错误指认结束本次挑战并保留悬念。

三个官方案件采用不同的推理结构，提供多样的询问体验：

| 案件 | 人物数 | 询问时间 | 推理关注点 |
| --- | ---: | ---: | --- |
| 空盒里的纪念章 | 3 | 8 分钟 | 物品交接与保管窗口 |
| 压轴怎么是鸭叫 | 4 | 10 分钟 | 播放内容与操作机会 |
| 盐和糖的小乌龙 | 4 | 9 分钟 | 原话、传话与实际执行 |

案件明确每个人知道什么、没见过什么、隐瞒什么。玩家通过多人的亲历交叉核对，逐步形成判断；关键结论不依赖角色认罪，也不靠结局临时补充事实。日常小事件题材和轻松的卡通表达，使推理具有亲近感。[案件目录](../../content/case-catalog.json)、[内容设计](../case-content-revision-2026-10-25/README.md)。

### 以鲜明品牌和细致交互塑造角色感

**LIE** 只有三个字母，简洁易记，直接呼应隐瞒、追问与判断。阳光黄、钴蓝、深蓝描边与暖白阅读面构成鲜明的视觉风格；品牌字标、人物、按钮、卡片和弹窗沿用统一设计语言，让首页、审讯、结果页和编辑器呈现完整一致的产品气质。[品牌素材](../../design/brand/README.md)、[视觉设计](../visual-direction.md)。

**八套人物形象都有多状态画面、动画和声音配置。** 聆听、等待、说话时的姿态随对话变化，让角色持续参与交流。人物的动态表现既增强角色感，也让玩家直观理解对话状态，成为整个产品体验的重要组成。[人物资源](../../design/character-presets/manifest.json)、[动画制作与接入](../animation/production-workflow.md)。

细节同样服务于交流：连接期间有醒目提示和取消入口，真正准备好才开始计时；切换角色保留各人的对话历史和共享时间；按钮、状态文字、人物动作与音频过程保持一致。玩家可以专注于询问，无需猜测系统是否正在收音或等待回答。[对话交互](../voice-connection-interaction.md)。

桌面与移动端都能直接在浏览器中游玩，无需安装客户端。响应式界面适配人物导航、对话记录和操作区域，也覆盖编辑、试玩与分享，让不同设备上的用户都能参与游玩和创作。[跨屏适配](../game-editor-implementation.md)。

### 低门槛 UGC 让内容持续扩展

LIE 为作者准备好人物美术、动画、声音和运行引擎。作者只需关注公共背景、角色设定和结局，选用预设形象，就能创作自己的案件，无需编程、绘画或搭建语音服务。

编辑器按故事、角色和结局组织创作，支持自由往返、本地草稿和同引擎试玩。完整案件压缩进分享链接，朋友打开即可进入；玩完还可以从当前案件继续改编。**创作、试玩、分享与改编构成相连的内容循环，游戏不再受限于官方预置案件。**[编辑器](../game-editor-implementation.md)、[分享机制](../../apps/web/src/editor/share.ts)、[改编功能](../remix-game-proposal/implementation.md)。

优秀作品还可通过“投稿给官方”进入收录流程。编辑器准备规范的案件 JSON，引导作者在 GitHub 完成提交和 Pull Request，由维护者评审收录。借助 GitHub 的版本记录、差异比较和审核机制，项目以简洁方式连接用户创作与官方内容，无需自建投稿后台，也不索取作者的 GitHub token。[投稿设计与实现](../editor-official-submission-proposal.md)。

### 围绕谎言与信任延展产品内涵

LIE 的品牌主题可以承载更多人与 AI 的博弈方式。未来可探索角色反转：玩家尝试撒谎，AI Agent 通过追问与核对作出判断。统一内容规格也为更多创作工具、人物资源和消费场景留出空间。

这些延展方向仍属未来探索。当前以三款官方案件和低门槛作者工具为起点，形成可游玩、可创作、可分享的产品基础；精品案件或主题定制等商业路径可在后续使用反馈中进一步验证。

## 二 架构设计

### 浏览器承担游戏逻辑 轻量云端连接 AI

游戏核心在浏览器中负责内容校验、会话、历史、询问额度和指认，薄 Cloudflare Worker 保管供应商连接凭据并转发语音协议。[整体架构](../architecture.md)。

**低基础设施成本与低运维负担是这一架构的直接优势。** 游戏计算和会话状态由玩家浏览器承担，内容随静态资源分发，省去了常驻游戏服务器、数据库备份和局进度存储管理。无共享游戏状态也减少了扩容时的状态协调工作，为从原型走向持续运营提供轻量基础。语音 AI 调用费用与供应商配额仍需单独考虑。

规则与 AI 表达各司其职：模型组织角色回答，程序判定答案和终局。切人、重开或结束时，编排器约束异步事件的归属，防止旧连接回包写入新的人物或会话。完整故事允许在浏览器中查看，供应商凭据保持服务端私密。[核心规则](../../packages/game-core/src/session.ts)、[对话编排](../../apps/web/src/application/controller.ts)、[薄网关](../../apps/gateway/src/index.ts)。

### 统一规格连接内容生产与运行消费

案件以纯文本描述故事与角色，只保留运行需要的结构；人物通过稳定 ID 引用可复用形象。新增同玩法案件只需内容与必要呈现配置，人数由内容决定，无需逐案修改通用引擎。

| 规格 | 生产端 | 消费端 |
| --- | --- | --- |
| 游戏包 | 作者与编辑器生成统一内容，核心校验结构与引用 | 同一引擎处理官方、试玩及分享案件 |
| 人物形象 | 权威清单定义状态图、主题与声音，生成器检查并输出资源 | 编辑器与游戏共用清单，故事按 ID 复用形象 |
| 动画包 | 部件、节点、轨道与状态遵循版本化契约 | 独立播放器按同一规格解析和播放 |

规格落实为文档、类型与校验器，生成逻辑和消费逻辑围绕相同契约实现。这为更开放的生产与消费社区打下基础：未来内容作者、工具开发者和运行端可以围绕统一规格协作，分别扩展创作工具、资源与使用场景。[游戏包规格](../../content/games/README.md)、[人物素材规格](../../design/character-presets/README.md)、[动画包规格](../animation/contract.md)。

### 自研轻量骨骼动画规格与播放器

LIE 自研轻量 2D 骨骼动画包规格及对应播放器，将位图部件绑定到层级节点，用枢轴、位移、旋转、缩放和显隐关键帧描述动作，再由 Canvas 2D 渲染。多个动作共用部件，默认、聆听、等待和说话状态通过数据映射到相应动画片段。[规格与类型](../../packages/character-animation/src/types.ts)。

播放器实现确定性采样、循环、状态切换与过渡，渲染器处理层级变换、绘制顺序、裁切和遮罩。核心独立于界面框架、具体案件和语音供应商，不同人物通过动画数据复用同一实现。版本、引用、资源尺寸和预算校验，以及静态回退，共同保障动画接入。[播放实现](../../packages/character-animation/src/playback.ts)、[运行时说明](../../packages/character-animation/README.md)。

这使人物制作成果能够持续转化为可交互的动态角色，也形成了可独立复用的动画技术资产。

### 按工业级交付要求推进性能工程

线上性能专项持续推进，覆盖网络瓶颈测量、案件加载链路、资源缓存、动画首帧和实际构建产物验证，让丰富的人物图片与动画具有相应的交付保障。

已有实现将官方三案随代码打包，减少打开案件的额外网络依赖；静态资源使用内容哈希 URL 与长期缓存，动画摘要覆盖完整包与部件。构建校验核对源文件、资源引用和最终产物，防止缺图、坏路径或错误缓存响应进入交付。[案件打包](../bundled-case-catalog.md)、[性能实现](../performance/2026-10-25/implementation.md)。

实际 Worker 产物的本地浏览器样本中，暖刷新时 13 项不可变资源的网络传输字节为零。线上整体收益将随专项交付继续测量。[测量记录](../performance/2026-10-25/browser-network.json)。

## 三 AI 价值呈现

### AI 将静态设定变为可以追问的角色

每个人物的经历、知识和隐瞒以文本定义，AI 根据玩家自由提出的问题组织回答。同一案件因询问顺序、表达方式和追问方向不同而产生不同的对话过程，玩家在交流中主动探索故事。

持续语音支持多轮交谈与打断，人物动作也随聆听、等待和说话状态变化。自然语言理解、角色表达、语音与视觉反馈共同构成玩法的核心体验。[持续语音设计](../architecture.md#已批准的持续对话与询问额度)。

### 角色知识边界让交叉询问具有意义

每次对话只向当前角色提供公共背景、本人设定和本人历史，不混入其他角色的私有设定或结局。端侧 MCP 工具绑定当前连接的人物，玩家转述的他人说法也保留为玩家输入，不自动变成角色亲历。[上下文装配](../../packages/game-core/src/context.ts)、[语音适配](../../apps/web/src/application/liveVoice.ts)。

这种设计保留了不同人物的信息差，使玩家有理由切换角色、核对口径和追问矛盾；固定答案由程序维护，让自由表达始终围绕可完成的游戏目标展开。

### 用真实行为评估持续打磨 AI 体验

项目将真实模型行为检查与程序测试分开：程序检查内容结构和事件处理，真实服务检查角色是否准确表达亲历、回应同义追问，以及如何处理玩家提供的虚假信息。持续语音已完成真人试用，移动端浏览器也已实际可用。

真实问答反馈已经用于澄清时间关系、改善关键信息的可达性和调整角色回答策略。评估保留原始结果与失败，推动内容和提示持续迭代；角色沉浸与最新内容仍在进一步回归完善。[角色行为评估](../case-behavior-validation.md)、[后续固定问题评估](../case-live-followup.md)、[最新内容修订](../case-content-revision-2026-10-25/README.md)。

## 四 AI 工程效率

### 全生命周期使用 AI 并持续改进协作

AI Agent 的工作贯穿设计、内容、开发、素材制作、测试与交付。项目同时持续改进分工、上下文传递和审查方式，将实际经验沉淀为仓库中的工作规范，让后续 Agent 可以复用。

**发现协作问题、调整工作方式、文档固化、后续复用**形成持续改进循环。例如，以完整交付批量汇报减少零散协调；将实施、配置和验收整体委派，保持主协调对决策和审查的专注；通过服务台账明确环境所有权与收尾责任。[协作规则](../../AGENTS.md)、[服务治理实践](../history/2026-10-25/development-service-cleanup.md)。

计划、交接和归档承担项目的长期记忆：有效决定、依赖、验证结果与未采用方案都可追溯，使跨任务、跨 Agent 的协作拥有共同依据。[项目记录](../project-plan.md)、[归档机制](../archive/README.md)。

### 模块化并行与独立审查保障交付

内容规则、语音、界面和视觉资源按职责分工，稳定契约与服务替身使不同模块可以并行推进。各任务使用独立 Git worktree 和分支，交付明确的依赖、提交和检查结果。

主协调审查完整 diff，由唯一集成人按序合入临时候选，完成相关验证后更新主干。并行执行与串行集成结合，让多个 Agent 的成果进入可审查、可验证的交付流程。[模块与独立测试](../architecture.md#模块拆解与独立测试)、[集成规则](../../AGENTS.md)。

### 把 AI 生成转化为可维护的产品资产

人物素材生成保留提示、来源与采用记录，动画制作进一步完成部件装配、姿态修订、接缝检查和运行接入。统一规格、资源生成器与播放器连接了 AI 制作和产品消费，让生成成果成为可复用、可检查的正式资产。[制作流程](../animation/production-workflow.md)、[资源生成器](../../scripts/character-presets.mjs)。

一轮动画组合验收通过 Web 281 项、UI 43 项和动画运行时 33 项测试，并核对八个动画包的 46 个部件引用。内容、协议、状态、界面与构建各层检查共同支持持续迭代。[组合报告](../animation/combined-final-animation-verification-2026-10-25.md)。

### 人类判断与有界实验共同控制成本

产品负责人把握玩法、架构、视觉与体验方向，Agent 承担执行、验证与反馈。实验预先明确目标和停止条件，优化也结合收益与成本决定是否采用。

例如，81 张 PNG 的无损压缩研究测得约 5.28% 的体积收益和 66.73 秒的处理耗时，项目据此暂不接入构建；角色沉浸实验在语义失败后停止，保留结果供后续判断。这种实践让 AI 工程能力体现为有依据的选择、可复用的成果和持续完善的协作机制。[PNG 研究](../performance/2026-10-25/png-lossless/README.md)、[有界角色实验](../role-immersion-investigation.md)。
