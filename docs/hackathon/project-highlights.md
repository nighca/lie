**开口询问，听出破绽。** LIE 是一款浏览器中的 AI 语音推理游戏：与各有经历和隐瞒的角色自由交谈，追问细节、核对说法，在有限时间内找出案件要求的目标人物。

**LIE 既是一款游戏，也是一个 AI 语音推理游戏平台。** 玩家可以体验精心设计的官方案件，也可以使用同一套人物资源、创作工具和运行引擎，制作、试玩、分享和改编自己的案件。AI 的自由表达、鲜明的视听体验与低门槛创作在这里连接起来，让游戏内容能够随创作者的想象持续扩展。

## 一 商业价值与产品设计

### 自由交谈与精心设计的推理相结合

玩家决定问什么、先问谁，以及何时打断或继续追问。语音是与角色交流的唯一方式，只读转写帮助回顾，最终通过按钮完成指认。有限的共享询问时间让自由谈话具有节奏与目标；正确指认揭晓完整经过，错误指认结束本次挑战并保留悬念。

六个官方案件采用不同的推理结构，提供多样的询问体验：

| 案件 | 人物数 | 询问时间 | 推理关注点 |
| --- | ---: | ---: | --- |
| 谁才是江苏人 | 2 | 2 分钟 | 旅行播客中两位嘉宾的家乡叙述与人物反差 |
| 这条线你真走了吗 | 3 | 6 分钟 | 徒步经历与路线说法的交叉核对 |
| 消失的纪念章 | 3 | 8 分钟 | 物品交接与保管窗口 |
| 压轴怎么是鸭叫 | 4 | 10 分钟 | 播放内容与操作机会 |
| 盐和糖的小乌龙 | 4 | 9 分钟 | 原话、传话与实际执行 |
| 这真是今天做的吗 | 3 | 8 分钟 | 既有成果与现场陈述的交叉核对 |

新入门案《谁才是江苏人》从旅行播客开场：玩家临时接替主持，与小周、小陈两位嘉宾聊家乡、吃喝和去哪里玩，再作出指认。两位虚构人物借地域梗形成轻松反差，不把口吻、城市认同或地域性格当作现实身份的判定规则；路演不提前揭晓正确目标。新增案沿用既有引擎与预设，旧四案仅顺移文件编号，原 ID 与 URL 保持不变。

当前首页江苏案第一、徒步案第二，六案询问额度为 2、6、8、10、9、8 分钟，人数由内容决定。

案件明确每个人知道什么、没见过什么、隐瞒什么。玩家通过多人的亲历交叉核对，逐步形成判断；关键结论不依赖角色认罪，也不靠结局临时补充事实。日常小事件与 Hackathon 现场题材，配合轻松的卡通表达，使推理具有亲近感。[案件内容](../../content/games/README.md)、[内容设计](../case-content-revision-2026-10-25/README.md)。

### 以鲜明品牌和细致交互塑造角色感

**LIE** 只有三个字母，简洁易记，直接呼应隐瞒、追问与判断。阳光黄、钴蓝、深蓝描边与暖白阅读面构成鲜明的视觉风格；品牌字标、人物、按钮、卡片和弹窗沿用统一设计语言，让首页、审讯、结果页和编辑器呈现完整一致的产品气质。[品牌素材](../../design/brand/README.md)、[视觉设计](../visual-direction.md)。

**八套人物形象都有多状态画面、动画和声音配置。** 默认、聆听、等待和说话四种基础状态随交流变化；正确或错误指认还会触发各自的结果反应，让角色从询问到揭晓都保持鲜活。人物的动态表现既增强角色感，也让玩家直观理解对话状态，成为整个产品体验的重要组成。[人物资源](../../design/character-presets/manifest.json)、[动画制作与接入](../animation/production-workflow.md)、[结果表现](../result-game-ui/final-main-verification.md)。

细节同样服务于交流：连接期间有醒目提示和取消入口，真正准备好才开始计时；切换角色保留各人的对话历史和共享时间；按钮、状态文字、人物动作与音频过程保持一致。玩家可以专注于询问，无需猜测系统是否正在收音或等待回答。[对话交互](../voice-connection-interaction.md)。

v1.1 继续完善从连接到结果的体验：用“正在请角色过来”“搬个椅子”等轻松提示解释等待，口供中的人物姓名沿用各自颜色高亮，便于核对说法；正确指认以庆祝动效与完整经过收束，错误指认保留真相，让玩家可以重新挑战。成功后优先返回案件列表，失败后优先重玩，按钮层级贴合两种不同的后续意图。[等待提示](../../apps/web/src/presentation/VoiceConnectionNotice.vue)、[姓名高亮](../../apps/web/src/presentation/CharacterNameText.vue)、[结果页设计](../design/result-page-ui/README.md)。

首次游玩时，时间数字旁的问号可打开“怎么算时间”，解释所有人物共享额度、连接准备不计时、停顿和等回答也计时，以及查看说明不会暂停。指认弹窗在选人前明确“点击人物会立即提交，结束本局；选错不会揭晓答案”，帮助玩家理解后果。Safari 音频问题仍在调查，已有诊断不等于兼容问题已修复。

桌面与移动端都能直接在浏览器中游玩，无需安装客户端。响应式界面适配人物导航、对话记录和操作区域，也覆盖编辑、试玩与分享，让不同设备上的用户都能参与游玩和创作。[跨屏适配](../game-editor-implementation.md)。

### 从一款游戏走向可持续创作的游戏平台

LIE 为作者准备好人物美术、动画、声音和运行引擎。作者只需关注公共背景、角色设定和结局，选用预设形象，就能创作自己的案件，无需编程、绘画或搭建语音服务。

编辑器按故事、角色和结局组织创作，支持自由往返、本地草稿和同引擎试玩。分享时保存当前案件快照并生成短链接，朋友打开即可进入；后续改稿不影响已经发出的快照，玩完还可以从当前案件继续改编。**创作、试玩、分享与改编构成相连的内容循环，游戏不再受限于官方预置案件。**[编辑器](../game-editor-implementation.md)、[分享机制](../../apps/web/src/editor/share.ts)、[改编功能](../remix-game-proposal/implementation.md)。

快照由私有 R2 存储，旧版压缩 fragment 链接仍可只读打开。分享不是云端草稿或账号同步：持有链接的人可以读取完整案件，包括真相；快照默认不过期，但不承诺永久可用，也没有作者撤回入口。作者的未分享草稿仍保存在当前浏览器。

### 让创作讨论直接进入表单

在提供 WebMCP 页面能力接口的浏览器中，编辑器可向能操作网页的助手提供创作规则、当前编辑版本与直接改稿工具。作者描述题材、人物或修改意图，助手便可把约定内容填入当前表单，继续使用同一套字段、规则和本地草稿保存，减少把讨论结果逐项复制到表单的手工搬运。页面提供“让 AI 帮你写”入口与实操指引；没有该接口时仍使用原有表单。

这条创作链路由用户的助手调用页面工具，产品侧没有新增创作模型服务。工具不返回完整原稿，只修改明确提供的字段，检查编辑版本和基本结构；写入后仍由作者检查故事，手动试玩、分享或投稿。工具不会自动开语音或分享，也不保证剧情质量。长期适配更多支持 WebMCP 的用户 Agent 是方向，目前不宣称已适配所有助手，亦未量化提效。现有验证覆盖工具写入、保存与界面行为，不等于创作质量或完整作者效率验证。

平台提供可复用的人物表现、统一内容规格与通用引擎，作者提供新的故事和角色设定；分享与改编让创作成果继续流动，官方收录则连接用户作品与平台内容。

优秀作品还可通过“投稿给官方”进入收录流程。编辑器准备规范的案件 JSON，引导作者在 GitHub 完成提交和 Pull Request，由维护者评审收录。借助 GitHub 的版本记录、差异比较和审核机制，项目以简洁方式连接用户创作与官方内容，无需自建投稿后台，也不索取作者的 GitHub token。[投稿设计与实现](../editor-official-submission-proposal.md)。

### 围绕谎言与信任延展产品内涵

LIE 的品牌主题可以承载更多人与 AI 的博弈方式。未来可探索角色反转：玩家尝试撒谎，AI Agent 通过追问与核对作出判断。统一内容规格也为更多创作工具、人物资源和消费场景留出空间。

这些延展方向仍属未来探索。当前以六款官方案件和低门槛作者工具为起点，形成可游玩、可创作、可分享的产品基础；精品案件或主题定制等商业路径可在后续使用反馈中进一步验证。

## 二 架构设计

### 浏览器承担游戏逻辑 轻量云端连接 AI

游戏核心在浏览器中负责内容校验、会话、历史、询问额度和指认。当前正式线上浏览器原生WSS直连Linx，薄Cloudflare Worker保管管理凭据并提供每局prepare、设备管理和分享服务；单prepare与本局凭据复用已生效。[整体架构](../architecture.md)。

**低基础设施成本与低运维负担是这一架构的直接优势。** 游戏计算和会话状态由玩家浏览器承担，官方内容随静态资源分发，用户分享快照由 R2 按链接读取；无需常驻游戏服务器或局进度数据库。无共享游戏状态也减少了扩容时的状态协调工作，为从原型走向持续运营提供轻量基础。语音 AI 调用、快照存储费用与供应商配额仍需单独考虑。

规则与 AI 表达各司其职：模型组织角色回答，程序判定答案和终局。切人、重开或结束时，编排器约束异步事件的归属，防止旧连接回包写入新的人物或会话。完整故事允许在浏览器中查看；供应商管理API key与签名secret保留服务端，直连方案只向本局浏览器提供临时Device token。[核心规则](../../packages/game-core/src/session.ts)、[对话编排](../../apps/web/src/application/controller.ts)、[薄网关](../../apps/gateway/src/index.ts)。

游玩与创作是两条不同的 AI 链路：当前线上游玩的音频、转写和角色上下文由浏览器直连Linx，gateway只准备身份/凭证并承担管理和分享服务；创作中，用户的 Agent 经 WebMCP 页面工具直接编辑浏览器中的表单。后一条复用现有编辑器与保存机制，无须另建产品侧创作模型后端，也不能把游戏角色模型当成已经接入的创作助手。页面工具注册依赖当前 Document 的能力，不能仅凭接口存在就断言 Agent 已在线。

### 统一规格连接内容生产与运行消费

案件以纯文本描述故事与角色，只保留运行需要的结构；人物通过稳定 ID 引用可复用形象。新增同玩法的官方案件只需增加一份带编号的 JSON，故事、简介、人物和结局共用这一内容源，首页目录与开局自动读取，无需另维护目录清单或内容副本。人数由内容决定，无需逐案修改通用引擎。[单文件内容入口](../../content/games/README.md)。

| 规格 | 生产端 | 消费端 |
| --- | --- | --- |
| 游戏包 | 作者与编辑器生成统一内容，核心校验结构与引用 | 同一引擎处理官方、试玩及分享案件 |
| 人物形象 | 权威清单定义状态图、主题与声音，生成器检查并输出资源 | 编辑器与游戏共用清单，故事按 ID 复用形象 |
| 动画包 | 部件、节点、轨道与状态遵循版本化契约 | 独立播放器按同一规格解析和播放 |

规格落实为文档、类型与校验器，生成逻辑和消费逻辑围绕相同契约实现。编辑器通过draftGame/validateGame产出GameDefinition，官方案、试玩快照与分享读取后都进入同一createGameController：创作者制作“背景＋人物＋结局”，玩家使用同一引擎询问、核对并指认。公开的是仓库契约和代码，不宣称行业标准或任意第三方引擎兼容。这为更开放的生产与消费社区打下基础：未来内容作者、工具开发者和运行端可以围绕统一规格协作，分别扩展创作工具、资源与使用场景。[游戏包规格](../../content/games/README.md)、[人物素材规格](../../design/character-presets/README.md)、[动画包规格](../animation/contract.md)。

### 已上线的浏览器直连与薄网关分工

介绍页一次POST prepare，由gateway根据签名Cookie与namespace分配浏览器Device/Client隔离身份，完成OTA及必要绑定/Agent归属检查，返回transport、Device/Client、临时token与期限。浏览器本局内存复用token，开始时等同一pending prepare，再原生WSS连接Linx `/v1/ws/`；Device/Client在URL，token在hello，不长期保存。音频、STT/TTS与MCP上下文不再经过Worker；静态资源、prepare、分享API与R2快照仍由托管端提供，管理API key/签名secret/设备管理仍在gateway。

token覆盖一局是本轮批准的工程假设，重试可重新prepare，新局重新准备；relay只保留为服务端明确配置的运营回滚，不自动fallback。该能力已随7ff正式发布；`/api/voice/status`已删除，健康GET不签Cookie、不做OTA/绑定。现行[每局prepare合同](https://github.com/nighca/lie/blob/7ff082483481f9e94979eb867c2ca575d5eff8b3/docs/reviews/voice-case-prepare-2026-11-03/README.md)替代旧status/per-open方案，文内候选阶段的待验状态由[正式发布记录](../releases/2026-11-03-direct-voice.md)覆盖。用户同SHA预览接受与生产部署不等于全部设备/真人语音场景或性能改善全验。

### 自研轻量骨骼动画规格与播放器

LIE 自研轻量 2D 骨骼动画包规格及对应播放器，将位图部件绑定到层级节点，用枢轴、位移、旋转、缩放和显隐关键帧描述动作，再由 Canvas 2D 渲染。多个动作共用部件，四种基础状态与正确、错误指认的两种结果状态通过数据映射到相应动画片段。[规格与类型](../../packages/character-animation/src/types.ts)。

播放器实现确定性采样、循环、基础状态切换与过渡，结果动作单次播放并停留在末帧；渲染器处理层级变换、绘制顺序、裁切和遮罩。核心独立于界面框架、具体案件和语音供应商，不同人物通过动画数据复用同一实现。版本、引用、资源尺寸和预算校验，以及静态回退，共同保障动画接入。[播放实现](../../packages/character-animation/src/playback.ts)、[运行时说明](../../packages/character-animation/README.md)。

这使人物制作成果能够持续转化为可交互的动态角色，也形成了可独立复用的动画技术资产。

### 以构建流水线落实性能工程

性能优化覆盖案件加载、图片派生、资源缓存和最终交付校验。官方案件在构建时由编号 JSON 自动收录，打开案件无需额外请求故事文件；人物原始 PNG 保留为制作源，构建自动生成 WebP q90，在保持尺寸与透明通道的同时减少运行时图片传输。[内容加载](../../apps/web/src/application/bundledCases.ts)、[图片优化方案](../performance/image-build-optimization/q90-approved.md)。

已测的 81 张图片样本中，PNG 约 66.49 MB，派生 WebP 约 9.75 MB，运行时图片字节减少约 **85.34%**。这项收益针对该图片集合；最终派生资源还会经过尺寸、透明通道、引用与完整性检查。[组合验收](../performance/image-build-optimization/combined-main-verification.md)、[浏览器验收](../performance/image-build-optimization/browser-acceptance.md)。

图片、动画包及清单使用内容哈希 URL 与长期缓存，更新内容生成新地址，未变化资源继续复用。CI 校验源文件和最终派生产物，再将同一份已验证构建交给 CD 发布；Linux 编码、实际发布与正式域名的 WebP、内容哈希及缓存响应均已有核验记录，让素材制作、构建和线上分发连成完整链路。[CI/CD 与线上核验](../releases/2026-10-25-q90-ci-cd/success.md)。

语音播放同样围绕实际反馈迭代：PCM 播放以 100ms 音频储备起播和恢复，连续排队时不逐片插入人为间隙，打断或关闭立即清理；浏览器播放上下文按 16kHz 配置。历史relay的默认600秒连接上限与Worker 30000ms CPU预算分别是连接墙钟与执行资源，不等于询问额度或费用硬上限；该旧中继资料不再作为本轮直连主讲/备页合同。这些实现与有限人工体验不构成全部设备、完整长会话的稳定性保证。[播放实现](../../packages/voice/src/player.ts)、[浏览器语音](../../apps/web/src/application/liveVoice.ts)、[网关配置](../../apps/gateway/cloudflare.config.ts)、[连接上限说明](../../apps/gateway/README.md)。

## 三 AI 价值呈现

### AI 将静态设定变为可以追问的角色

每个人物的经历、知识和隐瞒以文本定义，AI 根据玩家自由提出的问题组织回答。同一案件因询问顺序、表达方式和追问方向不同而产生不同的对话过程，玩家在交流中主动探索故事。

持续语音支持多轮交谈与打断，人物动作也随聆听、等待和说话状态变化。自然语言理解、角色表达、语音与视觉反馈共同构成玩法的核心体验。[持续语音设计](../architecture.md#已批准的持续对话与询问额度)。

### 角色知识边界让交叉询问具有意义

每次对话只向当前角色提供公共背景、本人设定和本人历史，不混入其他角色的私有设定或结局。端侧 MCP 工具绑定当前连接的人物，玩家转述的他人说法也保留为玩家输入，不自动变成角色亲历。[上下文装配](../../packages/game-core/src/context.ts)、[语音适配](../../apps/web/src/application/liveVoice.ts)。

这种设计保留了不同人物的信息差，使玩家有理由切换角色、核对口径和追问矛盾；固定答案由程序维护，让自由表达始终围绕可完成的游戏目标展开。

### 用真实行为评估持续打磨 AI 体验

项目将真实模型行为检查与程序测试分开：程序检查内容结构和事件处理，真实服务检查角色是否准确表达亲历、回应同义追问，以及如何处理玩家提供的虚假信息。持续语音已完成真人试用，移动端浏览器也已实际可用。

真实问答反馈已经用于澄清时间关系、改善关键信息的可达性和调整角色回答策略。评估保留原始结果与失败，推动内容和提示持续迭代；角色沉浸与最新内容仍在进一步回归完善。[角色行为评估](../case-behavior-validation.md)、[后续固定问题评估](../case-live-followup.md)、[最新内容修订](../case-content-revision-2026-10-25/README.md)。

## 四 AI 工程效率

### 全生命周期使用 AI 并持续改进协作

AI Agent 的工作贯穿设计、内容、开发、素材制作、测试与交付。项目同时持续改进分工、上下文传递和审查方式，将实际经验沉淀为仓库中的工作规范，让后续 Agent 可以复用。

**发现协作问题、调整工作方式、文档固化、后续复用**形成持续改进循环。例如，以完整交付批量汇报减少零散协调；将实施、配置和验收整体委派，保持主协调对决策和审查的专注；通过服务台账明确环境所有权与收尾责任。[协作规则](../../AGENTS.md)、[服务治理实践](../history/2026-10-25/development-service-cleanup.md)。

计划、交接和归档承担项目的长期记忆：有效决定、依赖、验证结果与未采用方案都可追溯，使跨任务、跨 Agent 的协作拥有共同依据。[项目记录](../project-plan.md)、[归档机制](../archive/README.md)。

### 协调 Agent 与 Worker 收口协作，设计先于落地

项目的职责可以归纳为协调 Agent 与 Worker 模型：人把握目标与关键设计，协调 Agent负责需求澄清、任务拆分、接口和依赖、审查与串行集成，Workers在独立工作区完成设计、实现、自验并交回完整证据。日常派工与结果收口交给协调 Agent，使人主要面对关键决策和可审成果，降低逐个Worker管理的负担；这是机制解释，尚无量化对照。这是职责分工描述，不代表采用某个同名SDK。

协调 Agent还通过定期检查待办持续推进已授权的遗留任务。本轮用户明确说明每30分钟检查；历史协调记录也保留该机制，但本次未查询当前自动化状态，不据此声称现时调度器已验证运行。重要产品、架构、供应商和范围决策仍需返回人确认。

“先设计”同时包括需求与约束、交互设计和技术方案，关键取舍确认后再实现验证与审查集成；WebMCP工具合同、版本/冲突保护及保存反馈与入口体验共同构成一个真实案例。该案例发生2026年11月1日，不纳入下方三天统计。需求先明确目的、影响范围与方案，关键设计确认后再落地；例行实现按已有授权推进，不要求每一行都单独人工审批。审查和真实验证继续反馈到设计，委派不转移发起者责任。

本次路演按2026年10月23–25日（北京时间）三天窗口统计：固定main可达785个提交（含文档/测试/素材），本机97 Agents（统计定义为14顶层Chat＋83显式子代理会话，含递归），自动审批已排除，同会话followup不增加计数，不是人数或并发。可读生命周期记录累计316,643,739ms，即5,277.39565 Agent分钟；路演以“>5,277 Agent分钟”呈现；本轮按用户反馈删除指标页最下覆盖说明，完整定义保留notes与内部证据：仅覆盖66/97会话，包含工具/等待与并行累加。31份缺失不估算，非全部Agent总工时或有效劳动时间，也不推导效率倍数。[统计方法与覆盖](../pitch/engineering-evidence-v6.md)。同三天固定范围另核19份设计/方案主文档，含未采用提案，不是19个已批准设计或全部设计材料；cutoff、去重清单与复现方法见[产出证据](../pitch/engineering-output-evidence-v10.md)。旧全时段952/33/142保留为历史，不能与本三天口径混用。

### 模块化并行与独立审查保障交付

内容规则、语音、界面和视觉资源按职责分工，稳定契约与服务替身使不同模块可以并行推进。各任务使用独立 Git worktree 和分支，交付明确的依赖、提交和检查结果。

主协调审查完整 diff，由唯一集成人按序合入临时候选，完成相关验证后更新主干。并行执行与串行集成结合，让多个 Agent 的成果进入可审查、可验证的交付流程。[模块与独立测试](../architecture.md#模块拆解与独立测试)、[集成规则](../../AGENTS.md)。

### 把 AI 生成转化为可维护的产品资产

人物素材生成保留提示、来源与采用记录，动画制作进一步完成部件装配、姿态修订、接缝检查和运行接入。统一规格、资源生成器与播放器连接了 AI 制作和产品消费，让生成成果成为可复用、可检查的正式资产。[制作流程](../animation/production-workflow.md)、[资源生成器](../../scripts/character-presets.mjs)。

八套人物的基础与结果动画进入统一的资源校验、运行时测试和组合验收，内容、协议、状态、界面与构建各层检查共同支持持续迭代。新增结果表现继续复用同一规格和播放器，而不是逐个人物编写专用逻辑。[动画与结果组合报告](../result-game-ui/final-main-verification.md)。

### 人类判断与有界实验共同控制成本

产品负责人把握玩法、架构、视觉与体验方向，Agent 承担执行、验证与反馈。实验预先明确目标和停止条件，优化也结合收益与成本决定是否采用。

例如，图片优化先比较无损压缩的收益与耗时，再经质量评估采用构建期 WebP q90，保留原图并自动检查派生资源；角色沉浸实验在语义失败后停止，保留结果供后续判断。这种实践让 AI 工程能力体现为有依据的选择、可复用的成果和持续完善的协作机制。[PNG 研究](../performance/2026-10-25/png-lossless/README.md)、[后续采用的 q90 方案](../performance/image-build-optimization/q90-approved.md)、[有界角色实验](../role-immersion-investigation.md)。
