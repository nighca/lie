# PNG lossless compression feasibility (read-only)

Historical estimate below. The later [complete Node/zlib corpus measurement](png-lossless/README.md) constructs actual candidate bytes and verifies CRC/filtered/RGBA/alpha identity: 81 PNGs, 5.28% potential saving, 66.73s compression time. That is the current evidence and recommendation; this older3.92% estimate is preserved as history. Neither experiment changes production assets or build behavior.

No PNG was rewritten, generated, reduced, resized, quantized, or AI-edited. The immutable pipeline copies original PNG bytes, so its pixel/alpha/color interpretation and metadata remain byte-identical by construction; the original strict byte check is retained.

Available compression tools checked: no `oxipng`, `optipng`, `pngcrush` or ImageMagick on PATH. System `sips` exists, but was not used because re-encoding can alter metadata. Python3.13.11 with zlib1.2.12 is available without installation.

Read-only experiment over **81** canonical PNG files at base d2a4eff (same PNG bytes as implementation base): concatenate IDAT payloads, inflate, recompress the identical filtered scanline stream with `zlib.compress(raw,9)`, estimate a single-IDAT PNG size while retaining every original non-IDAT chunk unchanged. Keep original when the estimate grows. Original total66,486,773 bytes; estimated63,882,569; potential saving2,604,204 (**3.92%**). Examples: sunny avatar963360→899767, silver default990099→944094, blue avatar864556→839597. Three ochre state files yielded no saving.

Observed non-IDAT chunk types were IHDR, caBX and IEND. No ICC/gAMA/sRGB chunk was present in the scanned files; caBX was retained in the estimate. A future implemented optimizer must keep all non-IDAT chunks in order (including any future color/profile data), validate original and output CRCs, retain identical inflated scanline data and IHDR, and independently compare decoded RGBA/alpha plus color interpretation. It must verify tool versions and actual generated bytes, not rely on this size estimate. No generated compressed PNG or decoded-pixel acceptance is claimed here.

Given the modest saving, compression was deliberately left out of this cache task. Canonical assets and generator/check semantics are unchanged. This report preserves the investigation outcome without adding a dependency or silently relaxing the strict byte check.
