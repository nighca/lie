# UI 设计对齐检查

2026-10-23，基于 `e329e62256bcc8d3a55e035d5ace04be1565c9fa`。依据用户已批准的 `design/ui/screens-flow.png`、`voice-and-results.png`、`spec.md`、`tokens.json`，逐项对照实际页面后实施。本轮不替换候选 Logo，不更改业务 controller、语音、案件内容或素材。

## 修正清单

| 区域 | 先前偏差 | 本轮调整 |
| --- | --- | --- |
| 接案 | 小头像、长内容靠左，主操作缺少视觉主次 | 居中暖白主卡、48px 级标题与珊瑚强调、大人物卡、独立三步流程、宽主按钮；正式案情保留完整 |
| 顶部 | 案名另起一行占据主内容区 | 审讯时案名与现有字标、结束、指认操作共同放在头部；保留演示标识 |
| 人物名单 | 横向小头像卡，与稿中纵向人物卡不同 | 纵向大头像和姓名，蓝色选中区与“当前人物”文字；窄视口改横向人物条 |
| 当前人物 | 低视口高度被压成240px整身小像 | 350–480px高的半身主角区、独立主题色背景形状；头像取景与主角取景分开 |
| 转写 | 转写被包进大面板，弱化对话关系 | 黄色画布上的独立描边气泡、说话人和头像；保留只读、折叠与独立滚动 |
| 语音控制 | 横跨人物名单，字号和符号偏小 | 位于人物与转写区下方的宽圆角控制条，80px符号、22px状态、清晰主次操作；等待、说话、错误符号区别明确 |
| 指认 | 只有文字按钮，缺少人物图 | 三张动态人物卡与直接指认按钮、居中标题、返回操作；错误提示使用暖白/水蓝内联区 |
| 结局 | 普通文本卡，层级弱 | 明确“指认正确”、大标题、静态轻装饰、完整经过区与宽重开按钮 |

UI继续消费通用数据，人物数量不写死。新增可选转写头像字段只服务展示；图片失败仍有文字姓名与首字。正文、按钮与状态使用既有 tokens；头像裁切是 CSS，未编辑 PNG。组件样式在本组件内覆写现有基础样式，未改根级主题或 lockfile。

## 验证

- 内置浏览器在1440×900设计基准、1280×720桌面视口检查接案、半身人物、模拟语音、转写气泡、指认、错误反馈、正确结局与重开。
- 1280×720审讯语音条底部约701px，主要语音操作在首屏内；额外说明可自然向下滚动，不固定高度裁掉内容。1440×900页面无横向溢出。
- 另用640×450窄布局检查横向人物条与纵向内容，无页面横向溢出。这是布局检查，不等同于真实浏览器200%缩放验收。
- Escape关闭原生dialog后焦点回到“最终指认”；原有键盘modal行为保留。折叠转写后切人仍保持折叠，历史保留，错误指认不揭晓；正确指认后显示正式完整经过。
- UI包5项测试、web包12项测试通过；UI/web类型检查、web生产构建通过。没有为纯CSS尺寸写镜像断言；未修改业务事件或增加流程。

修改前后 PNG 截图保存在该任务工作区 `tmp/ui-alignment/`（忽略的本地验证产物），包括 `before-interrogation-1280.png`、`before-interrogation-1440.png`、`after-interrogation-1280.png`、`after-interrogation-1440.png`、`after-accusation-1440.png`、`after-wrong-1280.png`、`after-solved-1280.png`、`after-narrow-640.png`。集成者保留需要的截图后可清理临时目录。

## 保持真实的差异

设计稿里的人物、案名和对白是占位；应用使用正式案件和既有预置静态形象，没有把参考图中的表情动作当成已实现动画。没有真实输入幅度时不绘制假波形；meter插槽仍供后续真实信号使用。当前solved投影只有结局文本，没有正确角色ID，本轮不把“当前对话人物”误当责任人来配图。品牌字标等待用户另选，不把Logo候选直接塞进界面。
