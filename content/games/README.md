# 案件内容作者规格

权威数据类型和校验器是 [`GameDefinition`、`CharacterDefinition`、`validateGame`](../../packages/game-core/src/content.ts)。本文解释已有契约，不增加第二套 schema、版本号、证据系统或故事规则语言。原始 JSON 经校验后只保留契约字段，所有纯文本原样保留，不自动 trim 或改写。

## 字段

| 字段 | 含义与实际约束 |
| --- | --- |
| `id` | 非空游戏标识。`loadGame(gameId, read)` 要求加载结果的 `id` 与请求值完全相同。核心不校验全站重名或文件路径；官方静态资源加载和投稿文件名另有边界。 |
| `title` | 非空案件标题，展示给玩家。 |
| `summary` | 手写公开简介纯文本；旧草稿/分享可省略，试玩和分享允许留空；官方编号JSON和投稿要求非空，不从background截取。 |
| `background` | 非空公共背景，一份纯文本。玩家接案时阅读，每位角色的上下文也包含同一份背景。不要放希望角色或玩家暂不知道的真相。 |
| `interrogationLimitSeconds` | 正安全整数秒，即 `Number.isSafeInteger(value) && value > 0`。每局所有人物共享语音启用时间；包含停顿、等待和回答，连接准备不计，结束对话后暂停，切人不重置。到期停止询问、进入指认，不自动判负或揭晓。 |
| `characters` | 非空人物数组。引擎没有固定三人限制，也不为人数另设上限；人物多寡由各案内容和实际使用体验决定。 |
| `characters[].id` | 本案内唯一的非空人物标识，按原字符串精确比较；切人、历史归属和正确答案引用它。不同游戏可以有相同人物 ID。 |
| `characters[].name` | 非空的本案人物姓名；不是预置形象的展示名，不要求角色名字与形象库 `name` 相同。 |
| `characters[].profile` | 非空的完整扮演设定，一份纯文本。写身份、口吻、亲历、所知与不知道的边界、隐瞒和被追问时的回答方式，不必拆成结构化事实表。该文本只加入这个角色的上下文，不加入其他角色的设定；完整游戏仍在浏览器可查，不提供秘密的安全隔离。 |
| `characters[].appearanceId` | 关联预置形象的 ID。核心允许 `null`（原始 JSON 未提供时也规范化为 `null`）；非空字符串不会在核心查询形象库。正式编辑器在试玩、分享和投稿前要求每个人物引用有效预置，分享读取器另拒绝失效的非空 ID。头像、立绘、状态、主题色和音色来自独立形象库，不复制进故事。 |
| `ending` | 指认判定与结局信息，由程序读取，不交给角色模型判断输赢。 |
| `ending.culpritId` | 唯一正确指认目标，非空且必须精确引用本案某个 `characters[].id`。字段名不意味着一定是凶杀题材；也可以是取走物品、换曲或其他谜题的责任人。 |
| `ending.reveal` | 非空完整真相纯文本。正确指认后展示；错误指认结束本局，不能在同一局改选，也不揭晓这段真相。 |

“非空文本”指字符串且 `value.trim().length > 0`，校验后返回原字符串；不要依赖校验器替作者清理首尾空格。ID 没有被核心额外限制为英文 slug：文件名安全、目录索引和内容分发是在核心之外处理的事情。核心检查字段与引用合法，不证明案件无矛盾、模型不编造或推理路径可解。

## 人物设定的写法

[`buildCharacterContext`](../../packages/game-core/src/context.ts)先写「你正在扮演{name}」，随后追加公共背景和「你的角色设定：」及原始 `profile`。推荐第二人称「你叫……」便于模型直接扮演，不是强制人称或新增结构规则。

例如：

> 你叫小林，负责整理道具，说话爽快。你把蓝杯收进左侧柜子，想等谢幕后再归位，尚未告诉别人。你看见小周从门口经过，但不知道他后来去了哪里。被问到杯子时如实说明放置位置；问到你没亲眼看见的事，直接说不知道。

完整真相可以写在这个角色应当知道的设定里；不要假设模型会自动读取其他人物的 `profile` 或 `ending.reveal`。涉及关键先后顺序、动作与知识边界，作者应写明确，再用真实对话验证。

## 最小合法形状

以下一人示例仅说明核心合法形状，不是推荐人数，也不证明有可玩的推理难度。`appearanceId: null` 展示核心容错，正式编辑器会要求选择预置形象后才可试玩或分享。

```json
{
  "id": "cup-story",
  "title": "蓝杯在哪里",
  "summary": "谢幕后蓝杯失踪了，问问整理道具的小林。",
  "background": "谢幕后，桌上的蓝杯不见了。请问清楚它被谁收到了哪里。",
  "interrogationLimitSeconds": 480,
  "characters": [
    {
      "id": "lin",
      "name": "小林",
      "profile": "你叫小林。你把蓝杯收进左侧柜子，想等谢幕后再归位。被问到时如实说明，不编造其他人的行动。",
      "appearanceId": null
    }
  ],
  "ending": {
    "culpritId": "lin",
    "reveal": "小林整理道具时把蓝杯收进了左侧柜子。"
  }
}
```

本目录是官方案件唯一内容源。新增官方案件只增加一个合法 `NN-<id>.json`（例如`04-new-story.json`），无需修改目录、import或registry；首页与开局共用eager glob。文件ID须与JSON内部id完全相同，原有`?game=<id>` URL不受前缀影响。前缀至少两位、正安全整数，按数值排序；支持100等超过两位序号，缺号可以保留。重复前缀（01/001视为同号）、重复id、命名/内容错误或缺少非空summary会使构建明确失败。没有order字段。

Editor故事步骤可写简介，本地草稿、试玩快照、分享fragment、改编和投稿JSON均保留。旧草稿恢复时缺简介补空字符串，旧分享缺字段继续可读；试玩/分享不因此被阻止。投稿前要求作者填写简介，文件名建议当前最大序号+1（最少两位）；作者仍在GitHub网页最终确认，发生并发同号由维护者合入时核对，不提供分配服务、OAuth或自动PR。已删除独立case-catalog和public/games副本。预置形象见[制作入口](../../design/character-presets/README.md)；[批准与历史](../../docs/builtin-case-json-proposal.md)。
